Ветка «записи DownloadManager нет»: скачанной считается только файл ожидаемой длины И с этой отметкой, иначе удаляется как мусор. Отметка снимается в start (вместе с записью id) и в remove (после удаления файла). Д-3: `cancel()` вызывает cancelActive только если запомненная загрузка не SUCCESSFUL (новый `isSuccessful(id)` — запрос курсора DownloadManager); успешную запись не трогает — её разберёт следующий status (проверит размер, поставит отметку, забудет). start/remove по-прежнему через cancelActive: start удаляет прежний файл сам, remove удаляет файл сам — для них успешная запись должна забываться.
- Шаг 4 (Д-3, Д-4, VoiceScreen.svelte): `readError` (текст отказа последнего чтения). refresh: успех — readError = null; отказ — всплывающее сообщение только если состояние уже известно (modelState !== null) и это первый отказ подряд (readError был null), иначе только запоминается — опрос раз в секунду больше не сыплет сообщениями. Новая ветка разметки: `modelState === null && readError !== null` — текст ошибки и кнопка «Повторить» (`run(refresh)`, блокировка busy). Д-3 на экране: после «Отменить» сообщение «Загрузка отменена» только если состояние не `downloaded` (если загрузка успела завершиться — apply уже сообщил «… скачана»).
- Шаг 5 (Д-5, voice-models.ts): без схемы `://` ввод отвергается при `/^https?[:/]|:\//i` (опечатки «http:/x», «http//x», «http:x», «https//x», пустой порт «x:/путь»); после разбора URL отвергаются порт 0 (`url.port === '0'`, в т. ч. «00») и имя пользователя/пароль. Порт в JSDoc — 1…65535. «0x7f.1» → 127.0.0.1 оставлено: это корректная запись IPv4 по WHATWG URL, не явная опечатка. Тесты: порт 0/00/с схемой; опечатки (6 случаев); «httpserver:8088» остаётся верным; учётные данные (3); IPv6 `[fe80::1]:8088` → `http://[fe80::1]:8088`, `http://[::1]/models/` → `http://[::1]/models`, `fe80::1` и `[fe80::1` → null.

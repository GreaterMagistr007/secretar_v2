# Ревью B12 — двенадцатый раунд саморевью этапа 3

Фокус: правдивость документации, соответствие требованиям, минимальность, чистота кода.
Дефекты логики — у ревьюера A12. Код не правился.

## Стартовый осмотр диффа

Проверяемые коммиты: `ce5f4e8` (тест `todayIso` + TZ тестов + записи в `docs/mechanic_tasks.md`,
`docs/history_sessions.md`), `2cc6e5d` (второе упоминание числа тестов в хронологии).
Затронуто: `docs/history_sessions.md`, `docs/mechanic_tasks.md`, `src/lib/date.test.ts`,
`vitest.config.ts`.

Утверждения, которые надо проверить фактом:
1. «206 тестов в семи файлах» — число и число файлов;
2. «покрытие измеряемых модулей — 100 % по строкам, ветвям и функциям»;
3. «Проверено мутацией: если `todayIso` переписать на `toISOString`, тест про поздний вечер падает»;
4. `env: { TZ: 'America/New_York' }` действительно меняет зону тестов (а не только `process.env`);
5. описан ли стенд тестов с зоной в `docs/tech_stack.md` и `docs/code_style.md`.

## Что подтверждено фактом (не находки)

- **206 тестов в семи файлах — верно.** Прогон в `node:22-alpine`: `Test Files 7 passed (7)`,
  `Tests 206 passed (206)`. По файлам: date 20, sort 16, text 28, validate 38, recurrence 50,
  memory-repository 46, id 8 = 206.
- **«покрытие измеряемых модулей — 100 % по строкам, ветвям и функциям» — верно.** `All files |
  100 | 100 | 100 | 100`, в измерение входят `date.ts`, `id.ts`, `memory-repository.ts`,
  `recurrence.ts`, `sort.ts`, `text.ts`, `validate.ts`.
- **`env: { TZ: 'America/New_York' }` реально меняет зону, а не только `process.env`.** Проверено
  отдельным тестом, примонтированным в контейнер поверх `src/lib/` (файлы проекта не менялись):
  `TZ= America/New_York offset= 240`, `new Date(2026, 8, 27, 23, 30).toISOString()` =
  `2026-09-28T03:30:00.000Z`.
- **Утверждение «Проверено мутацией: если `todayIso` переписать на `toISOString`, тест про поздний
  вечер падает» — верно и точно.** Прогон с примонтированным мутантом `date.ts`: падает ровно
  `× берёт локальные сутки, а не UTC: поздний вечер остаётся сегодняшним днём`, остальные 205
  зелёные. Заявление о единственном падающем тесте подтвердилось.
- Комментарии в `vitest.config.ts` и в `src/lib/date.test.ts` коду соответствуют: зона западная с
  ненулевым смещением (−240 мин), ожидания записаны литералами, `afterEach` возвращает реальные часы.

## Находки

### 1. Одиннадцатый и двенадцатый раунды в хронологию не попали, зато их число тестов задним числом вписано в девятый и десятый
**Важность:** важная
**Где:** `docs/history_sessions.md:61`, `docs/history_sessions.md:65-71`
**Что не так:** хронология обрывается на десятом раунде. Одиннадцатый раунд (коммиты `6c18626`,
`1a7cf94`: шесть важных находок ревьюера документации, правки комментариев `isStaleSelection`,
`dropStaleSelection`, `refreshToday`, свёрнутая запись В-11, роутер в разделе «Маршруты», новая
известная граница) и двенадцатый (`ce5f4e8`: переписанный тест `todayIso`, зона тестов) в ней не
описаны ни строкой. При этом оба последних коммита всё же правили хронологию — но не добавляли
запись, а меняли **число тестов в абзацах девятого и десятого раундов**. В результате девятый
раунд теперь утверждает результат, которого на тот момент не было.
**Доказательство:**
- `docs/history_sessions.md:61`: «Заодно заведены тесты на сам модуль дат... **Тестов стало 206 в
  семи файлах, покрытие измеряемых модулей — 100 %.**» — при этом сообщение коммита `1a7cf94`
  (одиннадцатый раунд, то есть ПОЗЖЕ девятого) заканчивается строкой «204 теста, svelte-check без
  ошибок»; 206 появилось только в `ce5f4e8`.
- `docs/history_sessions.md:67`: «Покрыта последняя непокрытая строка: **206 тестов, покрытие
  измеряемых модулей 100 %**» — то же для десятого раунда.
- После абзацев десятого раунда сразу идут «**Об инструменте:**» (строка 69), «**Открыто:**»
  (строка 71) и следующая по времени запись `## 2026-09-13 … 2026-09-15`; заголовка
  «Одиннадцатый раунд» в файле нет (`grep -n "раунд" docs/history_sessions.md` — последний
  найденный номер «Десятый»).
- Прецедент того же класса зафиксирован в самом файле, строка 43: «хронология обрывалась на
  третьем раунде» — числилось важной находкой пятого раунда.
**Что сделать:** вернуть в абзацы девятого и десятого раундов числа, которые там были на тот
момент (204), и добавить записи об одиннадцатом и двенадцатом раундах, где 206 и зона тестов
стоят на своём месте по времени.

### 2. Индекс памяти не знает об отчётах одиннадцатого раунда
**Важность:** замечание
**Где:** `memory/MEMORY.md:26-27` (конец перечня «Отчёты по этапу повторений и отметок»)
**Что не так:** перечень отчётов обрывается на десятом раунде, хотя `findings_review_a11.md` и
`findings_review_b11.md` добавлены в репозиторий коммитом `1a7cf94` (см. его `--stat`), а
`findings_review_a12.md` пишется сейчас.
**Доказательство:** последняя строка перечня — «`findings_review_a10.md`, `findings_review_b10.md`
— десятый раунд: корректность без важных находок, документация дала семь;
`findings_review_a10_partial.md` …»; строк про одиннадцатый раунд нет. `ls memory/` показывает
`findings_review_a11.md` (25 614 байт) и `findings_review_b11.md` (23 685 байт).
**Что сделать:** дописать строку об одиннадцатом раунде (и о двенадцатом, когда он закроется).
**Почему не важная:** `memory/` по правилам проекта — временное хранилище, потеря которого не
должна стоить проекту ничего; неверного действия из пропуска не следует. В четвёртом раунде
такая же находка была записана как важная — по нынешнему критерию это замечание.

### 3. Промпт следующей сессии остался с прежним числом тестов
**Важность:** замечание
**Где:** `memory/new-session-prompt.md:21`
**Что не так:** «204 теста в семи файлах зелёные» — фактически 206. Файл переписывается целиком в
конце сессии (`memory/MEMORY.md:18`), и следующая сессия начнёт с устаревшего числа.
**Доказательство:** `memory/new-session-prompt.md:21`: «204 теста в семи файлах зелёные,
`svelte-check` без ошибок, сборка проходит, покрытие измеряемых»; прогон даёт
`Tests 206 passed (206)`.
**Что сделать:** поправить число при обновлении промпта перед коммитом.

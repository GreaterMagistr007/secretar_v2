В фоне таймеры и анимации WebView тормозятся — сообщение может «досидеть» до возврата в приложение; приемлемо, но удаление должно идти от таймера, а не от `animationend` (последний в скрытой вкладке может не прийти).
- `prefers-reduced-motion`: в проекте не используется нигде (grep — пусто). Затухание прозрачности не является движением по WCAG 2.3.3, но правило стоит записать: при reduce — без затухания, 3 с видно, затем снятие.
- aria-live: контейнер с `role="status"`/`aria-live="polite"` держать в DOM постоянно (App.svelte), менять только содержимое — вставка нового узла с `role="status"` многими читалками не озвучивается; для error — `role="alert"` на вставляемом элементе допустимо. `pointer-events: none`, чтобы сообщение не перекрывало касания по списку; z-index выше кнопок (30) и ниже модалок (40).
### Н-22. Мелочь. Этап 1, расположение кнопки
- Проверено: `.screen` имеет `padding-bottom: calc(var(--space-lg) + 64px)` (CalendarScreen.svelte:600) — в конце прокрутки центр нижнего ряда ничего не перекрывает. При прокрутке длинного списка центральная кнопка закрывает середину строки задачи (текст), а «+» — только правый край; это заметнее. Столкновения с «+» нет даже на 320 px (центр 132–188 px, «+» 248–304 px). Безопасные отступы: `bottom` взять тот же, что у `.add` (:767); при горизонтальной ориентации с вырезом `left: 50%` центрирует по окну, а не по безопасной области — мелочь.

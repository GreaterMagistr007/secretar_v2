## ЧТО ДЕЛАТЬ ДАЛЬШЕ

1. **Сообщить владельцу в телеграм** (`tlg-send`) — его прямое указание по завершении цикла; если
   сообщение уже отправлено, пропустить.
2. **Вынести владельцу вариантами** (правило: варианты, плюсы, минусы, отдельная рекомендация):
   - **вопрос В-7** (устройство экрана календаря) — отобрать три макета из 30 и дать выбрать,
     порядок задан решением Р-28; это главная цель этапа по решению Р-12;
   - **правка контраста тем** по решению Р-26 (поднять пары ниже 3,0:1);
   - **`validateNewTask` приложением не вызывается** — модалка проверяет поля сама, получилось два
     способа проверять одно и то же; расхождение появилось до этапа повторений;
   - **роутер и состояние календаря не покрыты тестами** — руна `$state` на уровне модуля, тесты
     идут без плагина Svelte; вынос логики в обычные модули по образцу `isStaleSelection` — отдельная
     работа.
3. Из очереди MVP осталось: правка и удаление задачи (требования на них нет), экран поиска
   (требование Т-6, поиск в хранилище готов), Android через Capacitor (решение Р-20), серверная
   часть (Р-22, Р-23).

## Уроки цикла, записанные в правила
`docs/rules_work.md` пополнен тремя правилами, каждое с причиной из фактов: прогон считается зелёным
по коду возврата, а не по строке с числом; число в документации относится к моменту, и вписывать
нынешнее в запись о прошлом нельзя; перед коммитом проходить все сводные места поиском. Главное
наблюдение цикла: ложь в документации ни разу не оказалась там, где правили в прошлый раз — она
всплывала в соседнем абзаце того же файла или в старшем документе.

## Состояние проекта
Работающее PWA-приложение «Секретарь», опубликовано на `https://greatermagistr007.github.io/secretar_v2/`, репозиторий `https://github.com/GreaterMagistr007/secretar_v2` (публичный, ветка `master`, Pages собираются из GitHub Actions при каждом пуше).

Сделано:
- **Оболочка PWA**: манифест, service worker, иконки, установка на телефон, офлайн, сборка в docker.
- **Галерея из 30 макетов календаря** — `public/gallery/`, каталог на `/gallery/`, плюс справочная галерея прежнего проекта.
- **Система тем**: 40 дизайн-токенов, 30 тем, экран выбора с превью и зелёной галочкой, применение ко всему приложению, сохранение выбора, веб-шрифты с кириллицей.
- **Нижняя навигация** на всех экранах: «Календарь» и «Настройки».
- **Сущность «Задача»**: Dexie/IndexedDB, схема версии 1, UUID v7, создание через модалку (текст, дата, приоритет — все обязательные), список задач выбранного дня, полноэкранный просмотр `#/task/<id>`, метки приоритетов в сетке по реальным данным.
- **110 юнит-тестов**, все зелёные, покрытие логики 100 %, к базе тесты не обращаются.

Не сделано: отметки выполнения (требование Т-5), повторения (Т-4), правка и удаление задачи, экран поиска (само хранилище поиск умеет), Android через Capacitor, серверная часть.

## Как запускать и проверять
- Локально: `docker run -d --name secretar-dev -p 5173:5173 -v "$PWD":/app -w /app --user "$(id -u):$(id -g)" -e npm_config_cache=/tmp/.npm node:22-alpine npm run dev` → `http://localhost:5173/secretar_v2/`, с телефона в той же сети — по адресу машины (был `192.168.0.26`).
- Владелец просил **сначала показывать локально**, а публиковать после проверки: на Pages мешают ожидание сборки и кэш service worker.
- Проверки: `npm run check`, `npm run test`, `npm run build` — запускать в контейнере `node:22-alpine`, таймаут от 400000 мс.

## Правила, действующие постоянно
- Роль Claude: ведение документации, создание агентов, постановка задач, проверка их результатов (решение Р-6). Реализацию делают агенты; результат агента проверяется самостоятельно, а не принимается на веру.
- Каждое действие сразу фиксируется в документации (решение Р-7).
- По завершении этапа коммит и пуш — обязательны, без запроса (решение Р-8).
- Правка файлов внутри каталога проекта — без запроса (решение Р-9).
- Документация и память — только в каталоге проекта; глобальная память Claude не используется (решение Р-10).
- Вопросы владельцу — только вариантами с плюсами, минусами и рекомендацией; номер всегда с расшифровкой.
- MVP минимальный, берём только то, что можно сделать здесь и сейчас (решение Р-3).
- Отчёты агентов — в `memory/`, имя не начинается с `report`, запись дописыванием через Bash.
- Сообщение владельцу в Telegram — командой `tlg-send`, по его просьбе.

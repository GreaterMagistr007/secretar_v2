## Состояние проекта
Работающее PWA «Секретарь» на `https://greatermagistr007.github.io/secretar_v2/`, репозиторий
`GreaterMagistr007/secretar_v2` (публичный, `master`, Pages собираются из GitHub Actions на каждый пуш).

Сделано: оболочка PWA · галерея 30 макетов календаря · 40 дизайн-токенов, 30 тем, экран выбора темы,
веб-шрифты с кириллицей · нижняя навигация · сущность «Задача» (создание, список дня, просмотр) ·
повторения (Т-4) и отметки выполнения по конкретному повторению (Т-5).

**208 тестов в семи файлах, прогон зелёный по коду возврата** (проверено 2026-09-27), покрытие
измеряемых модулей 100 %, `svelte-check` и сборка чисты. К базам тесты не обращаются. Стенд работает
в зоне `America/New_York` — не в UTC: проект держится на плавающих датах из локальных полей `Date`,
а в UTC подмена локальных полей на UTC тестами не ловится вовсе. Менять зону нельзя, не проверив
мутацией, что тесты по-прежнему ловят такую подмену.

**Код в прошлой сессии не менялся ни строкой** — она была разбором: отбор по В-7 и перепроверка
фактов по трём остальным вопросам.

Не сделано: экран поиска (Т-6), правка и удаление задачи (В-14), Android через Capacitor (Р-20),
серверная часть (Р-22, Р-23).

## Как запускать и проверять
- Локально: `docker run -d --name secretar-dev -p 5173:5173 -v "$PWD":/app -w /app --user "$(id -u):$(id -g)" -e npm_config_cache=/tmp/.npm node:22-alpine npm run dev`
  → `http://localhost:5173/secretar_v2/`; с телефона в той же сети — по адресу машины. Контейнер с
  этим именем может быть уже поднят — сначала `docker ps --filter name=secretar-dev`.
- Проверки: `npm run test`, `npm run check`, `npm run build` — в контейнере `node:22-alpine`,
  таймаут от 400000 мс.
- **Прогон считается зелёным по коду возврата, а не по строке с числом тестов.**
- Владелец просил сначала показывать локально, публиковать после проверки: на Pages мешают ожидание
  сборки и кэш service worker.
- Браузерная проверка без расширения Claude in Chrome: `playwright-core` из кэша npx
  (`~/.npm/_npx/*/node_modules/playwright-core`) и Chromium из
  `~/.cache/ms-playwright/chromium-1243/chrome-linux64/chrome`. Приёмы — `memory/feedback_tooling.md`.
  Этим же способом отрисованы все 30 макетов галереи и снят экран приложения.

## Правила, действующие постоянно
- Роль Claude: документация, создание агентов, постановка задач, проверка их результатов (Р-6).
  Реализацию делают агенты; результат агента проверяется самостоятельно, а не принимается на веру.
- Каждое действие сразу фиксируется в документации (Р-7). По завершении этапа коммит и пуш —
  обязательны, без запроса (Р-8). Правка файлов проекта — без запроса (Р-9).
- Документация и память только в каталоге проекта; глобальная память Claude не используется (Р-10).
- Вопросы владельцу — только вариантами с плюсами, минусами и рекомендацией; номер с расшифровкой.
- MVP минимальный, берём только то, что можно сделать здесь и сейчас (Р-3).
- Отчёты агентов — в `memory/`, имя не начинается с `report`, запись дописыванием через Bash.
  Проверять агента не реже раза в 3 минуты.
- Claude никогда не деплоит: работа доводится до коммита и пуша.

## Уроки прошлой сессии
- **Параллельные агенты делят одну scratchpad-директорию и затирают файлы друг друга.** Двое
  независимо положили скрипт расчёта контраста под именем `wcag.py`, один затёр другой, прогон дал
  мусорные числа. Задавать агентам разные имена временных файлов.
- **Молчание агента — не смерть и не отказ инструмента.** Оба замолчавших агента ответили на прямой
  вопрос о живости и довели работу до конца; один молчал шесть минут, потому что пересчитывал
  испорченное соседом. Замена, запущенная на время молчания, дала не дубль, а сверку: числа совпали.
- **Рендер находит то, чего не видно в коде.** Горизонтальная прокрутка v06 на 360 px и фактические
  размеры ячеек получены только замером в браузере.
- Чужие утверждения — включая формулировки прошлой сессии в реестре вопросов — проверять по коду.
  Так нашлась зависимость `recurrence.ts` от `daysInMonth`, меняющая цену варианта «удалить валидатор».

# Короткое время на слух («в 7», «в три», «в пять»): варианты промпта на хосте (агент-исследователь, 2026-11-22)
Задача: на конфигурации APK 10 (окно 2048, MTP ON, один ход, сообщение нажатия USER_TEXT) сравнить 3–5 формулировок промпта/инструмента на всех записях журнала №4 с речью, найти ту, что возвращает время в «Завтра в 7 к стоматологу», «Завтра обед в три», «Сегодня в пять забрать машину» без регрессий и без роста ответа. Код приложения и docs/ не трогаются, ничего не коммитится.

## 0. Исходные данные
- Журнал memory/tmp_voicelog_20261122_5/raw/voice-log.jsonl: 21 нажатие с WAV, из них 19 с речью и ответом модели (015845 и 150116 — 200 мс, в модель не шли).
- Промпты сгенерированы из текущего кода (HEAD d1a98fe, src/lib/voice-command.ts и date.ts скопированы в gen/base, транспиляция scripts/transpile.cjs в контейнере secretar-dev-h33, scripts/gen.mjs): buildBasePrompt(момент нажатия из поля at, Asia/Irkutsk), USER_TEXT, ADD_TASK_TOOL → gen/prompts.json.
- Проверка: для 7 нажатий APK 10 (15:40–15:44) systemPrompt и userText из журнала совпадают с сгенерированными побайтно; нажатия APK 7/8 (01:58–15:04) на телефоне шли с прежним промптом — на хосте идут с текущим.

## 1. Окружение
- Контейнер secretar-litert-time (python:3.12.12-slim, litert-lm-api 0.19.1 с зеркала tuna), модель models/gemma-4-E2B-it.litertlm, записи, скрипты и промпты смонтированы только на чтение. CPU хоста, MNT 2048, SPEC ON (MTP), сэмплер topK 1 / temp 0, thinking off, один ход, max_output_tokens 128.
- Скрипты: scripts/variants.py (варианты как функции над промптом/инструментом/сообщением, замены с assert), scripts/table.py (таблица против ожидаемого, регрессии/улучшения к V0). Выход — out/*.jsonl.
- Ожидаемое (scripts/table.py, EXP): даты по ночному правилу (Р-38) и правилам промпта; короткое «в N» без суток («обед в три», «в четыре», «в пять») — по правилу промпта «как сказано» 03:00/04:00/05:00, по смыслу возможно 15:00/16:00/17:00 — СПОРНО, засчитываются оба; «в обед», «после обеда», «вечером» — без времени; text сравнивается строго (регистр и «ё» не важны), поэтому шум написания («Азон», «вайlbерис», «Корпоративный») считается промахом text во всех вариантах одинаково.

## 3. Варианты (scripts/variants.py) — точные тексты
- V1 (heard цифрами): строка промпта heard → «- heard — фраза дословно, как ты её услышал, без исправлений и пересказа; числа и время пиши цифрами: «в 7», «в 15:30».»
- V2 (явное правило): в конец строки промпта time после «„в 7“ — 07:00.» добавлено « Короткое «в N» рядом с днём или делом — это время: «завтра в 8 к врачу» — 08:00. Если на месте числа слышно «всем», «в сем», «с три» — это «в семь», «в три».» (пример намеренно не из записей, чтобы не подгонять).
- V3 (описание поля time в инструменте): «Время в формате ЧЧ:ММ, если названо числом — даже коротко «в 7»; иначе не передаётся.»
- V4 (подсказка в сообщении нажатия): USER_TEXT + « Время в ней часто названо коротко: «в 7», «в три».»
- V5 = V1 + V3; V6 = V1 + V2.
- Промежуточно (V1–V3 по четырём записям с коротким временем): «Завтра всем к стоматологу» не меняется ни в одном варианте — слово «всем» устойчиво; V2 возвращает «Сегодня в пять» → 22.11 17:00 и heard «Завтра обед с три» (но time нет); V3 ломает 140326: heard «Завтра обед с триКоманда пользователя — в аудиозаписи.» (модель вписала текст сообщения в heard).

## 5. Может ли код добрать время из heard (chrono-node/ru, без токенов модели)
Проверка `parse(heard, 2026-11-22 15:42, forwardDate)` в secretar-dev-h33: chrono-ru понимает только цифры — «Завтра в 7 к стоматологу» → 07:00; словесные «в пять», «в четыре», «в три», «обед с три» → час не найден; «Завтра всем к стоматологу» → только дата; «три часа дня» → 18:42 (ошибка chrono). Вывод: доборка времени кодом из heard работает лишь при heard цифрами и не помогает, когда heard уже «всем».
- Запущен второй круг: V0 повтор (детерминизм хоста), V7 (только правило короткого «в N»), V8 (только созвучия в строке time), V9 (heard цифрами — в описании инструмента), V10 (созвучия — в строке heard: «время пиши цифрами: «в 7», «в 3»; «всем», «с три» на месте времени — это «в 7», «в 3»»).

## 6. Звук: «Завтра обед в три» обрезан на последнем слове
- Уровни записей без клиппинга (пик 25 912–29 194 из 32 767, у пика 1–2 отсчёта).
- 140326-503 (1,8 с, holdMs 1660): огибающая по 20 мс в последние 0,3 с — 3324, 3506, 4315, 2457, 761, 483, 479, **4362** — речь идёт до последнего отсчёта, запись кончается посреди звука; у остальных записей в конце тишина (последние 100 мс — 63–225). Вероятно, кнопку отпустили на «три» и слово обрезано, — поэтому модель слышит «Завтра обед» / «Завтра обед с три» в любом варианте промпта. Это причина в записи, а не в промпте: лечится хвостом записи после отпускания кнопки (порядка 300 мс), а не формулировкой.

## 9. Выводы
1. Цель не достигнута ни одним из 10 вариантов: «Завтра в 7 к стоматологу» не исправляет ни один (0/10), «Завтра обед в три» — ни один (0/10; запись обрезана на «три», см. п. 6), «Сегодня в пять» получает время в 7 из 10 (17:00, по правилу промпта ожидалось бы 05:00 — спорно), правильную дату 22.11 — только V2.
2. Каждый вариант, возвращающий время «в пять», даёт хотя бы одну регрессию в остальных записях (дата «двадцать первого декабря» → 01.12/21.11, потеря «в четыре», «в обед» → 12:00, шум в text). Промпт на грани устойчивости: любое добавление текста перетасовывает 1–5 пограничных записей.
3. Токены: V1, V7, V8, V9 — не больше V0 (−1…−10 на 19 ответов); V2, V6 — +22, V10 — +15, V5 — +11, V3 — +15, V4 — +71. Рост там, где модель добавляет time (+10 токенов на поле) или выдумывает его.
4. Ближайший к цели — V2 (date 17/19, «в пять» → 22.11 17:00), но регрессия 015851 (21.12 → 01.12, ночной промпт) и «в обед» → 12:00 у 154023; без созвучий (V7) он хуже V0. Рекомендация: формулировку промпта ради короткого времени НЕ менять — выигрыш одной записи покупается регрессией другой, а две из трёх проблем промптом не лечатся.
5. Что может помочь вместо промпта (не проверено на телефоне):
   - хвост записи 300–500 мс после отпускания кнопки — против обрезанного последнего слова (140326);
   - подсказка владельцу/в интерфейсе: называть время полнее («в семь утра», «в 7 часов», «в три часа дня») — такие фразы распознаются стабильно (154137, 154322, 154420, 015851);
   - доборка кодом: chrono-ru берёт время только из цифр в heard («в 7» → 07:00), словесные «в пять/в три» и «всем» не понимает; правило «всем перед делом → 07:00» в коде возможно, но рискованно («позвонить всем») — только по решению владельца.

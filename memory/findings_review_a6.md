## Шаг 4. Проверенное и признанное корректным

**A. Календарь.** Инвариант «непустой список относится к выбранному дню» держится:
`CalendarScreen.svelte:238-240` очищает `dayOccurrences`, когда `loadedDate !== date`,
а `toggleCompletion` (строки 335-351) берёт день из самого вхождения
(`const day = occurrence.date`), а не из `calendarState.selectedDate`, поэтому даже
попадание в окно между отрисовкой и эффектом записало бы отметку на правильный день.
Два счётчика (`monthReloadToken`, `dayReloadToken`, строки 108-109) разведены верно:
`buildMarks` (строки 144-164) поле `done` не читает, поэтому отметка сетку не трогает.
Отказ чтения (строки 258-269) сбрасывает список и выставляет `loadedDate = date` —
инвариант «loadedDate — день последнего чтения» соблюдён на обеих ветках.

**B. Экран задачи.** Ветка `requested === null` (строки 29-35) из интерфейса недостижима:
`router.svelte.ts:34-39` отдаёт маршрут `/task` только при непустом идентификаторе.
Смена адреса без перемонтирования обрабатывается: эффект читает `id` (строка 26),
обнуляет `task` (строка 40) и отменяет прежнее чтение флагом `cancelled` (строки 64-66).

**C. recurrence.ts.** `occursOn` проверяет `date < start` первым (строки 78-80), поэтому
кратность семи (`weekly`) и совпадение числа (`monthly`/`yearly`) не дают ложных срабатываний
до старта. `monthly`/`yearly` через `Math.min(startDay, daysInMonth(...))` дают перенос
на последний день месяца (решение Р-25): старт 31 января → 28 февраля в невисокосном году,
29 февраля в високосном. `yearly` берёт `daysInMonth(year, startMonth)`, но это безопасно —
слева стоит `month === startMonth` и `&&` короткозамкнут. `dayNumber` через
`new Date(0)` + `setUTCFullYear` обходит правило `Date.UTC(26, …) === 1926`; `nextDay`
дополняет год до четырёх знаков. Перебор в `occurrencesInRange` ограничен числом суток,
бесконечного цикла нет.

**D. Хранилище.** Проверено отдельно утверждение комментария `dexie-repository.ts:72-74`
(«поле `recurrence` записывалось всем задачам и в версии 1»): это так —
`git show 282340f^:src/lib/tasks/dexie-repository.ts` показывает в `create` строку
`recurrence: 'none',`, и файл появился сразу с ней (первый коммит файла — 4b533b0).
Значит, задачи из базы версии 1 не выпадут из фильтра `task.recurrence === 'none'`
в `listOccurrencesByDate`/`listOccurrencesByRange`. Обратное было бы критической
находкой — записи стали бы невидимыми после обновления; проверка её не подтвердила.
Остальные расхождения реализаций совпадают с записанными в «Известные границы»
(`search` при обрезке, общий объект `task`, несуществующая дата в диапазоне,
`update` без чистки отметок, `setCompleted` для удалённой задачи).
Каскад в `remove` перечисляет обе таблицы в одной транзакции (строки 213-219),
удаление из `Set` во время `for…of` в памяти (строки 125-129) безопасно.

**E. Модалка.** Ловушка Tab не ломается на выключенной кнопке «Сохранить»:
селектор `button:not([disabled])` (строка 78) исключает её, и `last` становится
кнопкой «Отмена». Фон (`.backdrop`) лежит вне `bind:this={dialog}`, поэтому в перечень
не попадает и Tab на него не уходит. Дата снята с пропса через `untrack` (строка 38).
`z-index`: кнопка «+» — 30, оверлей выбора месяца — 40, оверлей модалки — 50,
так что открыть модалку поверх выбора месяца нельзя и два обработчика Esc не сталкиваются.

**F. Тесты.** `.only`/`.skip`/`.todo` не найдены. Тестов без утверждений нет (проверено
разбором тел всех `it(` по файлам `src/lib/tasks/*.test.ts`). `vitest.config.ts` не

## Находки

### В-1. Дата «сегодня» замораживается на время жизни экрана календаря
**Важность:** важная
**Где:** `src/routes/CalendarScreen.svelte:63-66`, использование — `:129`, `:459`, `:514`

**Что не так.** `today`, `todayYear`, `todayMonth` и `todayIsoDate` вычисляются один раз
при создании компонента и дальше не обновляются. Экран календаря — главный экран PWA
и живёт ровно столько, сколько пользователь на нём находится; телефон с открытым
приложением, переживший полночь, оставляет экран с вчерашним «сегодня».
Самое неприятное следствие — не подсветка, а дата новой задачи: модалка получает
`calendarState.selectedDate ?? todayIsoDate`, то есть при несделанном выборе дня
задача уходит на ВЧЕРА, молча и без признака ошибки. Правки задачи в интерфейсе нет
(требование Т-28 — только просмотр), удаления тоже, так что задача остаётся на
неправильном дне навсегда.

**Доказательство.**
```
63:  const today = new Date();
64:  const todayYear = today.getFullYear();
65:  const todayMonth = today.getMonth();
66:  const todayIsoDate = todayIso();
```
```
129:            isToday: toIsoDate(date) === todayIsoDate,
459:    initialDate={calendarState.selectedDate ?? todayIsoDate}
514:            class:month--current={index === todayMonth && pickerYear === todayYear}
```
Экран действительно переживает смену суток: `App.svelte:43-47` держит `<CalendarScreen />`
смонтированным всё время, пока маршрут — `/calendar`, а перезагрузки у установленной
PWA не происходит. Контрпроверка, что это не описано: в `docs/mechanic_tasks.md`,
раздел «Известные границы, оставленные сознательно», такой записи нет
(`grep -rn "todayIsoDate\|isToday\|initialDate" docs/*.md` — пусто), и ни в одном
из отчётов `memory/findings_review_a1…a5.md` и `b1…b5.md` этого нет.

**Что сделать.** Минимальный вариант — считать день в момент, когда он нужен:
заменить `todayIsoDate` на вызов `todayIso()` в месте использования (`:459` и `:129`
через параметр `buildWeeks`), либо, если владелец хочет и живую подсветку, завести
`$state` с датой и обновлять её по `visibilitychange`. Решение — за владельцем:
это правка за пределами этапа 3.

**Оговорка честности.** Код внесён не этапом 3 (строки 63-66 существуют с этапа 2,
`git show 282340f -- src/routes/CalendarScreen.svelte` их не трогает). Найдено при
сплошной проверке текущего состояния, как просила задача.

### З-1. Комментарий у `toggleError` обещает больше, чем делает код
**Важность:** замечание
**Где:** `src/routes/CalendarScreen.svelte:96-97` (правлено коммитом adb9888)

**Что не так.** Комментарий: «Сам эффект гасит toggleError при каждом чтении списка —
и при смене дня, и при перечитывании того же дня». Присваивание стоит ДО ветки,
в которой чтения не происходит вовсе, поэтому список случаев неполон: сообщение
гаснет ещё и при снятии выбора дня, когда никакого чтения нет.

**Доказательство.**
```
224:    toggleError = null;
225:
226:    if (date === null) {
227:      dayOccurrences = [];
228:      loadedDate = null;
229:      dayLoading = false;
230:      dayError = null;
231:
232:      return;
233:    }
```
Поведение при этом правильное — вместе с выбором исчезает и весь блок списка
(`:430` `{#if calendarState.selectedDate !== null}`), так что показывать сообщение
негде. Неверен только перечень в комментарии.

**Что сделать.** Дописать третий случай — «и при снятии выбора дня» — либо
сформулировать через повод: «гасится при каждом перезапуске эффекта списка».

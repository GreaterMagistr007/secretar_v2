### Т-3. Важно (DRY, минимальность). Доли @keyframes продублированы из TOAST_TIMING; есть вариант без дублирования и с одной анимацией вместо двух
- Файлы: src/lib/components/Toast.svelte:84-94, 112-138; src/lib/toast.ts:30-37 (комментарий «меняются вместе»).
- Сейчас: две @keyframes с жёсткими 33,333 % и 66,667 %, два правила `animation-name` по типам, предупреждения о синхронизации в трёх местах (toast.ts:31, Toast.svelte:107-110, mechanic_toast.md). Рассинхрон не ловится ни одним тестом: мутация «fadeMs заменён константой» проходит; `visibleMs` и `fadeMs` по отдельности в коде нигде не используются — только их сумма.
- Предложение: одна `@keyframes toast-fade { from { opacity: 1 } to { opacity: 0 } }` в `.toast` с `animation: toast-fade var(--toast-fade) linear var(--toast-visible) both`, где в инлайн-стиле `style:--toast-visible="{TOAST_TIMING[type].visibleMs}ms"` и `style:--toast-fade="{TOAST_TIMING[type].fadeMs}ms"`. `fill-mode: both` держит opacity 1 во время задержки. Уходят: вторая @keyframes, два правила с `animation-name`, все три предупреждения «меняются вместе», комментарий про переименование имени в классах типа (имя одно и стоит в `.toast`). Разбиение `visibleMs`/`fadeMs` в TOAST_TIMING начинает реально использоваться.

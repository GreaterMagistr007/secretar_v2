## A3-1. Сообщение об ошибке чтения задач дня НЕ показывается никогда: вместо него вечная «Загрузка задач…»

**Важность:** критическая (пользователь получает неснимаемый обман вместо ошибки; ветка `{:else if error !== null}` мертва)

**Где:** `src/routes/CalendarScreen.svelte:249-252` и `:419`, `src/lib/components/DayTaskList.svelte:51-54`

**Что не так.** Правка второго раунда связала показ списка с равенством `loadedDate` и выбранного дня, но в ветке отказа чтения `loadedDate` сбрасывается в `null`. Выбранный день при этом не `null` (иначе компонент не отрисован вовсе), значит `stale` истинно, и первое же условие шаблона перехватывает отрисовку до ветки ошибки. Экран показывает «Загрузка задач…», хотя ничего не грузится и `dayLoading === false`.

**Доказательство.**

Ветка отказа эффекта списка дня, `src/routes/CalendarScreen.svelte:244-253`:

```
      .catch(() => {
        if (cancelled) {
          return;
        }

        dayOccurrences = [];
        loadedDate = null;
        dayError = 'Не удалось прочитать задачи дня.';
        dayLoading = false;
      });
```

Компонент отрисовывается только при непустом выбранном дне, `src/routes/CalendarScreen.svelte:414-421`:

```
  {#if calendarState.selectedDate !== null}
    <DayTaskList
      date={calendarState.selectedDate}
      occurrences={dayOccurrences}
      loading={dayLoading}
      stale={loadedDate !== calendarState.selectedDate}
      error={dayError}
```

То есть после отказа `stale = (null !== '2026-09-27') = true`. Шаблон, `src/lib/components/DayTaskList.svelte:51-54`:

```
  {#if stale || (loading && occurrences.length === 0)}
    <p class="hint">Загрузка задач…</p>
  {:else if error !== null}
    <p class="hint hint--error" role="alert">{error}</p>
```

`stale` истинно → ветка ошибки недостижима. Другого места вывода `dayError` в экране нет: `grep -n 'dayError' src/routes/CalendarScreen.svelte` даёт только объявление (`:78`), сброс в эффекте (`:223`, `:231`), присваивание в `catch` (`:251`) и передачу пропом (`:420`).

Состояние неснимаемо изнутри дня: повторный щелчок по той же ячейке вызывает `calendarState.select(cell.iso)` с тем же значением, а `selectedDate = date` тем же значением реактивность `$state` не поднимает (`src/lib/calendar-state.svelte.ts:52`), значит эффект не перезапускается и повторного чтения не будет. Выйти можно только выбрав другой день.

То же и для перечитывания после отметки: при успешной записи `dayReloadToken += 1` (`:328`) перезапускает эффект; если это чтение упадёт, `loadedDate` обнулится и список, который был на экране, сменится на вечную «Загрузку» без объяснения.

**Что сделать.** В ветке отказа не трогать `loadedDate`, а признак «данные чужого дня» строить так, чтобы отказ до него не дотягивался: например, в `catch` присвоить `loadedDate = date` (данные для этого дня прочитаны — пусто и с ошибкой), либо считать `stale` только когда `dayError === null`, либо передавать в компонент не `stale`, а сам `loadedDate` и сравнивать с `date` уже после проверки ошибки.

## A3-2. Отказ записи отметки, случившийся после ухода с дня и возврата на него, всё равно показывается

**Важность:** замечание

**Где:** `src/routes/CalendarScreen.svelte:322-334`

**Что не так.** Проверка «результат наш» сравнивает выбранный день только в момент прихода ответа и не различает «день не менялся» и «день сменился и вернулся». За время записи эффект успевает перечитать день заново и обнулить `toggleError` (`:217`), после чего отклонённое обещание ставит сообщение поверх свежего списка — рядом с флажком, состояние которого уже прочитано из базы и верно.

**Доказательство.** `src/routes/CalendarScreen.svelte:319-335`:

```
  async function toggleCompletion(occurrence: Occurrence, done: boolean): Promise<void> {
    // Пока идёт запись, пользователь может выбрать другой день. Результат тогда не наш:
    // сообщение об отказе встало бы под чужим списком, а перечитывание тронуло бы чужой день.
    const day = occurrence.date;

    try {
      await taskRepository.setCompleted(occurrence.task.id, day, done);

      if (calendarState.selectedDate === day) {
        dayReloadToken += 1;
      }
    } catch {
      if (calendarState.selectedDate === day) {
        toggleError = 'Не удалось сохранить отметку.';
      }
    }
  }
```

Сценарий: день X → щелчок по флажку (запись идёт) → день Y → снова день X (эффект читает заново, `toggleError = null`) → запись отклоняется, `calendarState.selectedDate === day` истинно → сообщение появляется. Порча данных из этого не следует: в базе ничего не менялось, флажок показывает прочитанное. Вреда мало — отсюда и важность.

**Что сделать.** Либо признать поведение верным (сообщение об отказе правдиво: запись для этого дня действительно не удалась) и снять из комментария обещание «результат тогда не наш», либо привязать результат к конкретному запуску эффекта, а не к значению дня: запоминать счётчик/маркер запуска и применять результат только при совпадении маркера.

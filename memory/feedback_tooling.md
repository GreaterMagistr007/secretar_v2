# Грабли инструмента

Только про поведение Claude Code, не про продукт. Продуктовые выводы и решения — в `../docs/`.

## Режим auto mode блокирует запись в `.claude/settings.json` (2026-09-13, подтверждено)
**Симптом:** создание `.claude/settings.json` отклоняется с текстом `Permission for this action was denied by the Claude Code auto mode classifier. Reason: [Self-Modification]`. Отказ приходит без диалога с владельцем — вопрос до него не доходит.
**Что проверено:** отклонены обе попытки — Bash-heredoc и инструмент `Write`. В глобальном `~/.claude/settings.json` в `permissions.allow` уже есть `Bash(*)`, и это от отказа не спасло: классификатор смотрит на характер действия, а не на permission-правило. Подсказка в тексте отказа («добавьте Bash permission rule») этим контрпримером не подтверждается.
**Обход, который сработал:** владелец переключил режим сессии на `accept edits`, после чего файл записался обычным инструментом `Write` без дополнительных запросов.
**Как действовать дальше:** правки `.claude/settings.json` и других настроек Claude Code выполнять из режима `accept edits`. Из auto mode — не пытаться: это не вопрос формулировки команды.

## Хуки кэшируются на момент старта сессии (2026-09-13)
Созданный `.claude/settings.json` в текущей сессии не действует: нужен `/hooks` или перезапуск. Следствие — проверить разрешения «на ходу» невозможно, поэтому хуки проверялись прогоном их команд напрямую через `sh -c` с подстановкой JSON на stdin.

## Смена режима сессии меняет набор запросов подтверждения (2026-09-13, подтверждено)
**Симптом:** после выхода из auto mode в режим `accept edits` подтверждения начали появляться на каждое действие браузерных инструментов Claude in Chrome — переход по ссылке, снятие скриншота.
**Причина:** `acceptEdits` авто-одобряет только правки файлов; все прочие инструменты идут через обычные permission-правила. В глобальном `~/.claude/settings.json` в `permissions.allow` браузерных инструментов нет (там `Read`, `Glob`, `Grep`, `WebSearch`, `WebFetch`, `Agent`, `Bash(*)`, `mcp__gitlab__*`, `mcp__sentry__*`), поэтому каждый вызов `mcp__claude-in-chrome__*` спрашивал.
**Побочный эффект:** снятие скриншота дважды завершилось ошибкой `CDP sendCommand "Page.captureScreenshot" timed out after 30000ms` — таймаут CDP истекал, пока ждали подтверждения.
**Что сделано:** в проектный `.claude/settings.json` добавлены `mcp__claude-in-chrome__*`, `Bash`, `Monitor`, `Agent`, `WebFetch`, `WebSearch` и фоновые задачи — и в `permissions.allow`, и отдельными блоками хуков `PreToolUse` и `PermissionRequest`. Применяется со следующей сессии (хуки кэшируются на старте).
**Чего это не снимает:** собственные диалоги расширения Claude in Chrome в браузере — они настраиваются в самом расширении, разрешением для конкретного сайта.

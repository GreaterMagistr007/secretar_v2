# Ревью скептика: коммит f205dad — выбор и докачка модели в «Настройки → Голос» (Р-36)
Дата: 2026-11-21. Скептик кода не меняет. Находки Д-N: уровень, файл:строка, доказательство, предложение.

## Д-1. Блокер. Файл модели 2,6 ГБ попадает в Auto Backup: облачная резервная копия всех данных приложения (включая задачи) перестаёт делаться
- Где: `android/app/src/main/AndroidManifest.xml:10` (`android:allowBackup="true"`, правил `fullBackupContent`/`dataExtractionRules` нет, в `res/xml/` только `config.xml`, `file_paths.xml`); `ModelDownloaderPlugin.java:86,229` — файл в `getExternalFilesDir("models")`.
- Доказательство (developer.android.com/identity/data/autobackup, прочитано 2026-11-21): по умолчанию Auto Backup включает «Files on external storage in the directory returned by getExternalFilesDir(String)»; квота 25 МБ на приложение; «If the amount of data is over 25 MB, the system calls onQuotaExceeded() and doesn't back up data to the cloud». Задачи живут в IndexedDB WebView (`app_webview`, каталог `getDir`) — тоже в копии. Итог: после скачивания модели облачная копия приложения целиком перестаёт обновляться, задачи владельца молча остаются без резервной копии. Отдельно: при переносе телефон→телефон (D2D, без квоты) будут копироваться 2,6 ГБ; SharedPreferences `model_downloader` (id загрузки) переедут на новое устройство, где этот id ничего не значит (самоисцеляется через `forget()`, но это побочный эффект).
- В документации (`docs/mechanic_voice.md`, `docs/mechanic_android.md`) о резервной копии ничего нет — проверено grep по «резервн», «backup».
- Предложение (минимально): `res/xml/backup_rules.xml` (`<full-backup-content>`) и `res/xml/data_extraction_rules.xml` (`<cloud-backup>` и `<device-transfer>`) с `<exclude domain="external" path="models"/>` и `<exclude domain="sharedpref" path="model_downloader.xml"/>`; ссылки `android:fullBackupContent` и `android:dataExtractionRules` в манифесте. Проверка: `adb shell bmgr backupnow <пакет>` и `dumpsys backup` / размер в логе. Альтернатива дешевле, но хуже: `allowBackup="false"` — лишает копии и задачи.

## Д-2. Важно. Файл полного размера без записи DownloadManager признаётся скачанной моделью — проверка размера при предвыделении файла ничего не доказывает
- Где: `ModelDownloaderPlugin.java:193-203` (ветка «записи нет» → `forget()` → `target.length() == expectedSize` → `downloaded`).
- Доказательство: сам исполнитель зафиксировал (журнал, шаг «перезапуск посреди скачивания»; `docs/mechanic_voice.md:70`), что DownloadManager сразу выделяет файл полного размера 2 588 147 712. Если запись загрузки исчезнет посреди скачивания, не удалив файл (очистка данных приложения «Загрузки»/Download Manager в настройках телефона, чистка БД провайдером), следующий `status` попадёт в ветку «записи нет», увидит файл ровно ожидаемой длины и ответит «Скачана, 2,59 ГБ» для недокачанного файла. Удаление записи через системный UI файл удаляет, а очистка данных провайдера — удаляет строки, но не файлы `DESTINATION_FILE_URI` (по исходникам AOSP, на устройстве не проверено). Вероятность низкая, но последствие — модель-мусор, которую потом получит LiteRT-LM.
- Предложение (несколько строк): при `STATUS_SUCCESSFUL` с верным размером запоминать в prefs признак «файл <имя> проверен»; в ветке без записи считать файл скачанным только при этом признаке, иначе удалять как мусор; в `remove`/`start` признак снимать. Альтернатива дороже — SHA-256 на телефоне (2,6 ГБ, 10–30 с).

## Д-3. Замечание. «Отменить» в момент завершения загрузки удаляет готовый файл
- Где: `ModelDownloaderPlugin.java:121-125, 213-221`; `VoiceScreen.svelte:147-153`.
- Доказательство: `cancelActive()` вызывает `DownloadManager.remove(id)` без проверки статуса. Если загрузка уже `SUCCESSFUL`, но опрос (раз в секунду) ещё не успел `forget()`, `remove(id)` удалит скачанные 2,6 ГБ, а экран покажет «Загрузка отменена». Окно ≤1 с, ущерб — повторная докачка.
- Предложение: в `cancelActive` перед `remove` запросить статус и при `SUCCESSFUL` только `forget()`. Либо принять и не трогать.

## Д-8. Замечание. deployment.md: совет про ufw неверен для docker — опубликованный порт открыт на всех интерфейсах мимо ufw
- Где: `docs/deployment.md` (раздел «Модель для голоса…», строка про брандмауэр); `docker-compose.yml` `ports: "${MODEL_PORT:-8088}:80"`.
- Доказательство: docker публикует порт правилами iptables, которые срабатывают до цепочек ufw (документация Docker «Packet filtering and firewalls», раздел про ufw) — `ufw allow 8088/tcp` не нужен, а `ufw deny` порт не закроет. Модель публичная (Apache 2.0 указана в доке) — утечки нет, но текст вводит в заблуждение.
- Предложение: заменить строку про ufw на «docker открывает порт мимо ufw; на чужой сети раздачу не запускать / остановить после докачки». Опционально `ports: "${MODEL_BIND:-0.0.0.0}:${MODEL_PORT:-8088}:80"` — не обязательно.

## Д-11. Замечание. `docker-compose.yml`: логика докачки верна по всем веткам, мелкие остатки
Разбор `model-download` (busybox `sh`):
- нет файла и `.part` — `wget -c` качает с нуля, сумма, `mv` — верно;
- оборванный `.part` — `wget -c` с `Range`; при новом обрыве размер < `MODEL_SIZE` → `exit 1`, `.part` остаётся — верно;
- полный `.part` с битым байтом — 416 → ошибка `wget`, но размер не меньше → проверка суммы → `rm` → `exit 1` (следующий запуск с нуля) — верно; `.part` длиннее файла — так же;
- `wget` успешен, содержимое чужое (страница ошибки) — сумма не сошлась → `rm` — верно;
- ошибка до первого байта (нет сети, 404/401) — `stat` падает → `0` → `exit 1` — верно;
- готовый файл с верной суммой — `exit 0` (хеширование 2,6 ГБ при каждом `up model-server`, ~8,5 с — приемлемо).
Остатки:
- готовый файл с НЕВЕРНОЙ суммой (порча на диске) не удаляется: качается полный `.part` рядом — нужно ещё 2,6 ГБ (в deployment.md «около 2,6 ГБ свободного места»), а уже запущенный `model-server` до `mv` раздаёт битый файл, который телефон примет по размеру. Редкий случай; можно `rm -f "$MODEL_FILE"` перед загрузкой.
- nginx отдаёт весь `./models`, включая `.gitkeep` и `.part` во время повторной загрузки, — безвредно.
- `alpine:3.22` закреплён по минорной версии (как `node:22-alpine` в Dockerfile — так принято в проекте), `nginx:1.30.6-alpine` — по патчу; правила закрепления в `docs/code_style.md` нет. Не дефект.
- Модель в git не попадает: `git check-ignore` → `.gitignore:39 models/*`, в индексе только `models/.gitkeep`. В APK и `dist/` не попадает (не в `public/`). Контекст сборки образов: `COPY`/`ADD` в Dockerfile нет, BuildKit 2,6 ГБ не передаёт.

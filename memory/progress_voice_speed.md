## Факты LiteRT-LM 0.19.1 о замерах (исходники тега v0.19.1, https://codeload.github.com/google-ai-edge/LiteRT-LM/tar.gz/refs/tags/v0.19.1)
- `kotlin/.../Benchmark.kt`: `data class BenchmarkInfo(initTimeInSecond, timeToFirstTokenInSecond, lastPrefillTokenCount, lastDecodeTokenCount, lastPrefillTokensPerSecond, lastDecodeTokensPerSecond, markDurationsInSecond: Map<String,Double>, maxNumTokens)`.
- `Conversation.kt:682` `@ExperimentalApi fun getBenchmarkInfo()` → `LiteRtLmJni.nativeConversationGetBenchmarkInfo`; `Conversation.getTokenCount()` — без opt-in.
- Включение: `ExperimentalFlags.enableBenchmark` («read only when a new Engine is created») → `Engine.initialize` передаёт в `nativeCreateEngine`; JNI `litertlm.cc:730-731`: `if (enable_benchmark) settings->GetMutableBenchmarkParams();` — параметры по умолчанию (num_prefill_tokens=0, num_decode_tokens=0).
- При нулевых параметрах вход не подменяется: `runtime/core/session_utils.cc:66-78` (`ids.resize(...)` только если num_prefill_tokens > 0), `session_advanced.cc:73,119` (то же), декод останавливается по стоп-токенам как обычно: `tasks.cc:96-107` `ShouldStop` (`benchmark_decode_token_count == 0` → обычная остановка).
- Цена включения: `tasks.cc:613-614` — с бенчмарком prefill ждёт завершения (`SetWaitForCompletion(... | benchmark_info.has_value())`); остальное — запись меток времени. Декоду всё равно нужен готовый prefill — заметного замедления не ожидается (проверяется замером).
- Время аудиоэнкодера: `serial_execution_manager.cc:679,686` (и threaded_execution_manager.cc:703,710) — `TimeMarkDelta("audio_executor")` вокруг `audio_executor->Encode(spectrogram)` → `markDurationsInSecond["audio_executor"]`. Токены звука вливаются в общий список (`combined_token_ids.insert(... num_audio_tokens, kSpecialToken)`) — отдельного счётчика токенов звука в Java нет.
- JNI `CreateBenchmarkInfoJni` (litertlm.cc:138-200): отдаёт только ПОСЛЕДНИЙ ход prefill и декода (токены и ток/с), сумму фаз инициализации (`initTimeInSecond`, по фазам — только VLOG), все метки. TTFT (`io_types.cc:357-367`) = длительность ПЕРВОГО хода prefill + средний первый токен декода.
- Решение: `prefillPrefaceOnInit = true` — системный промпт и описание инструмента читаются при создании разговора отдельным ходом prefill; бенчмарк после создания = prefill промпта (токены, ток/с), после ответа = prefill хода пользователя (звук + текст + шаблон), декод (токены, ток/с), метка `audio_executor`. TTFT библиотеки при этом относится к промпту, поэтому время до первого токена ответа считается: звук + prefill хода + один токен декода. Объём работы модели тот же (те же токены, два хода prefill вместо одного).

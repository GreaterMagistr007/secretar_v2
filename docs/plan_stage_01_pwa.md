# Этап 1: оболочка PWA и публикация

Цель этапа — не функционал, а работающий канал доставки: приложение открывается на телефоне по ссылке, ставится на домашний экран, работает офлайн и обновляется после пуша. Функционал задачника в этот этап не входит (решение Р-3 — минимальный MVP).

Закрывает позиции каталога 1 (оболочка PWA), 2 (главный экран с надписью «Секретарь»), 14 (публикация на GitHub Pages) и требования Т-14 (название приложения), Т-15 (стартовый экран первой поставки), Т-16 (установка как PWA), Т-17 (русский язык интерфейса).

## Состав работ

### 1. Каркас проекта
- `package.json` со скриптами `dev`, `build`, `preview`, `check`; зависимости и версии — [tech_stack.md](tech_stack.md).
- `vite.config.ts`: `base: '/secretar_v2/'`, плагины Svelte и PWA.
- `tsconfig.json` со строгим режимом (`strict: true`), `svelte.config.js`.
- `index.html`: `<html lang="ru">`, `<title>Секретарь</title>`.
- `src/main.ts`, `src/App.svelte`, `src/app.css`.

### 2. Главный экран
Экран с надписью «Секретарь» — больше ничего. Оформление сдержанное, с CSS-переменными под тему, чтобы дизайн подбирался правкой значений. Вёрстка под телефон: `viewport` с `viewport-fit=cover`, безопасные зоны (`env(safe-area-inset-*)`), никакой горизонтальной прокрутки.

### 3. PWA
- Манифест: `name` и `short_name` — «Секретарь», `lang: "ru"`, `display: "standalone"`, `start_url` и `scope` — `/secretar_v2/`, `theme_color`, `background_color`.
- Иконки: 192×192, 512×512 и maskable 512×512, плюс `apple-touch-icon` 180×180.
- Service worker через `vite-plugin-pwa` с `registerType: 'autoUpdate'`: прекэш оболочки, обновление подхватывается при следующем открытии.
- Офлайн: после первой загрузки приложение открывается без сети.

### 4. Окружение сборки
- `Dockerfile` на `node:22-alpine` и `docker-compose.yml` с сервисами `dev` (порт 5173, хост `0.0.0.0`), `build`, `check` — решение Р-17 (окружение сборки в контейнере).
- Пути в контейнере и на хосте одинаковые, платформенно-зависимого кода нет.

### 5. Публикация
- `.github/workflows/deploy.yml`: сборка на Node 22, публикация `dist/` через `actions/upload-pages-artifact` и `actions/deploy-pages`; триггеры — пуш в `master` и `workflow_dispatch`; права `pages: write`, `id-token: write`, `contents: read`; `concurrency` на группу `pages`.
- Разовая настройка в интерфейсе GitHub выполняется владельцем — [deployment.md](deployment.md).

## Критерии приёмки
1. `npm run build` проходит без ошибок и предупреждений типизации; `npm run check` чистый.
2. В `dist/` лежат `index.html`, манифест, service worker, иконки; все ссылки на ассеты начинаются с `/secretar_v2/`.
3. Локальный просмотр собранной версии показывает экран с надписью «Секретарь», заголовок вкладки — «Секретарь».
4. Манифест валиден: `name` и `short_name` — «Секретарь», указаны иконки 192 и 512, есть maskable.
5. Service worker регистрируется, при выключенной сети страница открывается из кэша.
6. Workflow синтаксически корректен, собирает и публикует артефакт.
7. Ни `TODO`, ни `FIXME`, ни заглушек в коде нет.
8. Горизонтальной прокрутки на ширине 360 px нет.

## Порядок проверки результата
Claude проверяет сам, не полагаясь на отчёт агента (решение Р-6 — проверка результатов работы агентов): сборка запускается, содержимое `dist/` осматривается, манифест читается, ссылки на ассеты проверяются на префикс `base`, экран открывается в браузере.

## Что в этот этап не входит
Календарь, экран задачи, экран настроек, хранилище, поиск, повторения. Они идут следующими этапами, первым из них — экран «Календарь» (требование Т-11), после ответов на вопрос В-6 (маршрут создания задачи из календаря) и вопрос В-7 (устройство экрана календаря).

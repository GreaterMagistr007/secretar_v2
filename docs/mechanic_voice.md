# Механика: голос (модель и её докачка)

Реализована 2026-11-21 по решению Р-36 (модель — отдельный файл, докачивается в «Настройки → Голос» из локальной сети), уточняющему Р-34 (голос — только в APK, офлайн, локальной моделью со звуком на входе). План и выбор владельца — [plan_stage_05_voice.md](plan_stage_05_voice.md), раздел «Выбор владельца 2026-11-21 (2): доставка модели». Сделана только доставка модели: записи звука, кнопки «слушать», запуска модели (LiteRT-LM) и скачивания с Hugging Face из приложения нет.

## Модели
- Каталог — `VOICE_MODELS` в `src/lib/voice-models.ts`, одна запись: `gemma-4-e2b`, «Gemma 4 E2B», файл `gemma-4-E2B-it.litertlm`, 2 588 147 712 байт. Первая запись — модель по умолчанию.
- Веб-часть: `localStorage` — `secretar.voice.model` (id выбранной модели; неизвестный id читается как модель по умолчанию) и `secretar.voice.server` (адрес сервера раздачи как введён). Недоступное хранилище — как у остальных настроек: значение действует в сеансе, но не запоминается.
- Нативная часть: `SharedPreferences` `model_downloader` — `download_id` (номер загрузки DownloadManager) и `file_name`, пусто — загрузки нет; `verified_file` — имя файла, чья загрузка завершилась успешно с верным размером (отметка «проверен»).
- Файл модели на устройстве: `getExternalFilesDir("models")/<имя файла>` = `/sdcard/Android/data/io.github.greatermagistr007.secretar/files/models/`. Почему не `filesDir`: DownloadManager работает в своём процессе и пишет только во внешнее хранилище; каталог приложения во внешнем хранилище не требует разрешений, приватен для приложения на Android 11+ и удаляется вместе с приложением. Рантайм модели принимает путь к файлу, копировать в `filesDir` не нужно.
- **Резервная копия Android:** файл модели (`external`, `models`) и `model_downloader.xml` (`sharedpref`) исключены из Auto Backup и переноса на новый телефон — `res/xml/backup_rules.xml` (Android ≤11) и `res/xml/data_extraction_rules.xml` (Android 12+), см. [mechanic_android.md](mechanic_android.md), «Резервная копия». Без этого модель 2,6 ГБ превышала квоту облачной копии (25 МБ), и копия приложения вместе с задачами не делалась вовсе (проверено на эмуляторе: «Size quota exceeded»). После восстановления или переноса модель скачивается заново.

  - «Не скачана» + «Скачать»;
  - «Скачивается: X МБ из Y МБ (Z %)» + полоса `progress`, при паузе DownloadManager — строка причины («Нет связи с сервером, повтор через некоторое время», «Ждёт подключения к сети», «Ждёт Wi-Fi»), кнопка «Отменить»;
  - «Скачана, 2,59 ГБ» + «Удалить модель»;
  - отказ плагина при чтении состояния, пока оно ещё не известно, — текст «Не удалось узнать состояние модели: …» и кнопка «Повторить».
  В браузере — пояснение, что модель скачивается и работает только в Android-приложении, кнопок нет.
- Всплывающие сообщения (`showToast`, [mechanic_toast.md](mechanic_toast.md)): ошибка — неверный адрес («Введите адрес сервера», «Неверный адрес сервера: …»), отказ плагина, ошибка загрузки с причиной от нативной части; успех — «Gemma 4 E2B скачана» (переход «качается → скачана» при открытом экране), «Загрузка отменена» (не показывается, если загрузка успела завершиться до отмены — модель остаётся), «Gemma 4 E2B удалена». Отказ чтения состояния при уже известном состоянии (например, во время опроса) — всплывающее сообщение только при первом отказе подряд, а не каждую секунду.
- Прогресс опрашивается раз в секунду, только пока модель качается и экран открыт; при возвращении в приложение (`visibilitychange`) состояние перечитывается. Сама загрузка идёт и без экрана — её ведёт система, прогресс виден в шторке.

## Сервисы

### Чистая логика — `src/lib/voice-models.ts`
- `findVoiceModel(id)`, `loadVoiceModel` / `saveVoiceModel`, `loadServerAddress` / `saveServerAddress`.
- `normalizeServerAddress(input)` → `схема://хост[:порт][/путь]` без `/` в конце или `null`: пробелы по краям убираются; без схемы — `http://`; ввод без `://`, похожий на опечатку в схеме или с пустым портом (`http:/x`, `http//x`, `http:x`, `x:/путь`), — неверно: иначе «http» стал бы именем хоста; разбор `URL` (порт вне 1…65535, порт 0, пробел в хосте — неверно); только `http`/`https`; адрес с `?` или `#` — неверно (к нему не приписать имя файла); адрес с именем пользователя или паролем — неверно (раздача их не принимает); IPv6 — только в скобках (`[fe80::1]:8088`); порт по умолчанию схемы опускается (`:80` для http). Порт 8088 сам не подставляется: `http://host` однозначно значит порт 80.
- `modelFileUrl(server, model)` — адрес сервера + `/` + `encodeURIComponent(имя файла)`.
- `formatMegabytes` (десятичные МБ, вниз, разряды неразрывным пробелом), `formatGigabytes` (два знака: «2,59 ГБ»), `downloadPercent` (вниз, 0…100, `null` при неизвестном или нулевом размере).

### Мост — `src/lib/model-downloader.ts`
По образцу `task-notifier.ts`: `registerPlugin('ModelDownloader')`, `isModelDownloaderAvailable()` = `Capacitor.isNativePlatform()`. `startModelDownload(model, url)`, `readModelState(model)` — `null` в браузере; `cancelModelDownload()`, `removeModel(model)` — в браузере ничего не делают. `parseModelState(raw)` проверяет ответ целиком: `absent` / `downloading { downloaded, total | null, paused | null }` / `downloaded { size }` / `error { reason }`; неверный ответ — `error` с его текстом, чтобы экран не показал неправду.

### Нативная часть — `android/app/src/main/java/io/github/greatermagistr007/secretar/`
- `ModelDownloadState` — чистая логика, JUnit-тесты `ModelDownloadStateTest` (прогоняются задачей `test` сборки APK): состояние по записи DownloadManager (`PENDING`/`RUNNING` — качается; `PAUSED` — качается с причиной; `SUCCESSFUL` — скачана только при размере файла, равном ожидаемому, иначе ошибка; `FAILED` — ошибка с текстом по коду HTTP или `ERROR_*`), тексты причин, `isSafeFileName` (плагин удаляет файл по имени — без `/`, `\`, `\0`, `.`, `..`). Константы DownloadManager — константы времени компиляции, javac подставляет их, поэтому тесту эмулятор не нужен. Код `400` DownloadManager ставит и сам, без обращения к серверу, — так он отказывает в HTTP без шифрования; текст причины говорит об обоих вариантах.
- `ModelDownloaderPlugin` — плагин Capacitor `ModelDownloader`, зарегистрирован в `MainActivity` рядом с `TaskNotifierPlugin`:
  - `start({ url, fileName, size, title })` — отменяет прежнюю загрузку, удаляет прежний файл (DownloadManager не перезаписывает, а качает рядом под именем «…-1»), ставит `DownloadManager.Request` с `setDestinationInExternalFilesDir(..., "models", fileName)` и уведомлением о ходе загрузки, запоминает id и снимает отметку `verified_file`; адрес не http/https — отказ;
  - `status({ fileName, size })` — по запомненной загрузке, а без неё по файлу. Завершившаяся загрузка забывается: успешная с верным размером — файл отмечается `verified_file`, загрузка только забывается (`DownloadManager.remove` удалил бы и готовый файл); ошибка и неверный размер — `remove(id)` вместе с файлом; ошибка отдаётся веб-части один раз. Записи нет (отменили в системных «Загрузках», очистили данные «Диспетчера загрузок») — забыть. Без загрузки скачанной считается только файл ожидаемой длины с отметкой `verified_file`; любой другой файл удаляется как мусор: DownloadManager выделяет файл сразу полного размера, и по длине недокачанный не отличить от готового;
  - `cancel()` — `DownloadManager.remove(id)`: удаляет и недокачанный файл. Если загрузка уже завершилась успешно (нажали «Отменить» в последнюю секунду, до опроса), ничего не делает: файл остаётся, загрузку разберёт следующий `status`;
  - `remove({ fileName })` — отменяет загрузку этого файла, удаляет файл, снимает отметку `verified_file`.
  Размер читается `getData().optLong`, а не `getLong`: `PluginCall.getLong` Capacitor отдаёт `null` для числа, уместившегося в int.
- HTTP без шифрования: `android:usesCleartextTraffic="true"` в манифесте, см. [mechanic_android.md](mechanic_android.md), «HTTP без шифрования».

### Раздача модели с компьютера — `docker-compose.yml`
Команды и как узнать адрес — [deployment.md](deployment.md), раздел «Модель для голоса: раздача в локальной сети».
- `model-download` (`alpine:3.22`, от пользователя хоста): качает `https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm/resolve/<ревизия>/gemma-4-E2B-it.litertlm` в `models/<файл>.part` (`wget -c` — оборванная загрузка продолжается), проверяет SHA-256 и только потом переименовывает. Ревизия закреплена — commit `2e12bfd869b2962984f97a1f2a26807316d534cc` (поле `sha` API Hugging Face, 2026-11-20); SHA-256 `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c` (`lfs.oid` файла на этой ревизии). Файл с верной суммой повторно не качается; готовый файл с неверной суммой (порча на диске) удаляется перед загрузкой — иначе уже запущенный `model-server` раздавал бы его до конца перекачки. Полный `.part` с неверной суммой удаляется (иначе `wget -c` получал бы 416 и застревал).
- `model-server` (`nginx:1.30.6-alpine`): `./models` только на чтение, порт `${MODEL_PORT:-8088}`; отдаёт `Content-Length`, `ETag` и `Range` (206) — без `ETag` и `Range` DownloadManager не продолжил бы загрузку после обрыва. Ждёт успешного `model-download`.
- `models/` в `.gitignore` (`models/*`, кроме `models/.gitkeep`): каталог должен быть в клоне, иначе docker создаёт его от root и `model-download` не может писать.

## Примечания

### Известные границы
- **DownloadManager при обрыве сам повторяет попытки** (паузы растут: 2, 2, 4 мин и дальше) и после нескольких неудач завершает загрузку ошибкой — до ошибки около 15–20 минут повторов. Пока он ждёт, экран показывает «Скачивается: …» и «Нет связи с сервером, повтор через некоторое время»; отменить можно сразу. Так же выглядит и неверный адрес, указывающий на несуществующий компьютер, — проверку адреса заранее DownloadManager не делает.
- **Сеть загрузки не ограничена Wi-Fi** (`setAllowedNetworkTypes` не задан): при переходе телефона с Wi-Fi на мобильную сеть DownloadManager попытается продолжить через неё, адрес локальной сети оттуда недостижим — экран покажет паузу «Нет связи…», после возврата в Wi-Fi загрузка продолжится (на устройстве не проверено, тест-кейс 14).
- **Файл выделяется сразу полного размера**: во время загрузки размер файла на диске уже 2 588 147 712 — по нему нельзя судить о прогрессе. Проверка размера после успеха ловит другой файл на сервере (другой `Content-Length`); обрезанную передачу DownloadManager сам завершает ошибкой.
- **Принудительная остановка приложения загрузку не прерывает** — её ведёт системный процесс загрузок.
- **«Отменить» в последнюю секунду**, когда загрузка уже завершилась, файл не удаляет: модель остаётся скачанной, экран сообщает «Gemma 4 E2B скачана».
- **Резервная копия и перенос на новый телефон** модель и состояние её загрузки не содержат — после восстановления модель скачивается заново.
- **Подтверждения перед «Удалить модель» нет**: удаление обратимо повторной докачкой (по локальной сети около полутора минут на эмуляторе).
- HTTP разрешён приложению целиком, а не только для локальной сети, — см. mechanic_android.md.
- Свободного места DownloadManager требует сам; при нехватке — ошибка «Недостаточно места на телефоне» (на эмуляторе не воспроизводилась: раздел данных расширен до 6 ГБ).

### Проверка на эмуляторе
2026-11-21, Android 15 (SDK 35, `google_apis` x86_64, образ `secretar-emu-check`, `-partition-size 6144` — в AVD образа раздел данных 2 ГБ), APK `versionCode 5`. Протокол — `memory/progress_voice_model_download.md`. Адрес сервера из эмулятора — LAN-адрес компьютера (`192.168.0.26:8088`): эмулятор в docker выходит в сеть через контейнер; `10.0.2.2` эмулятора — сам контейнер, не компьютер; доступен и `172.17.0.1:8088` (шлюз `docker0`).
- Без разрешения HTTP DownloadManager отказал: `Cleartext traffic not permitted for package ...`, статус 400. С `usesCleartextTraffic` — качает.
- Полное скачивание за 83 с, «Скачана, 2,59 ГБ», `ls -l` — 2588147712 байт, SHA-256 на устройстве совпадает с Hugging Face.
- Перезапуск приложения при скачанной модели и посреди скачивания (`am force-stop`) — состояние и прогресс восстановлены.
- Отмена на 18 % — файл удалён, «Загрузка отменена».
- Обрыв: сервер остановлен на 71 % и запущен через минуту — DownloadManager докачал остаток по `Range` (nginx: `206`, 747 951 408 байт), сумма верна.
- Удаление — каталог пуст.
- Неверный адрес: синтаксически неверный — сообщение без загрузки; нет файла — «На сервере нет файла модели (HTTP 404)»; закрытый порт — пауза «Нет связи с сервером, повтор через некоторое время», DownloadManager повторял попытки через 2, 2 и 4 мин и после пятой завершил загрузку ошибкой (`ERROR_HTTP_DATA_ERROR`) — экран сам перешёл в «Не скачана» со всплывающей ошибкой. По этому прогону текст ошибки `ERROR_HTTP_DATA_ERROR` заменён на «Нет связи с сервером: проверьте адрес и что раздача запущена» — так DownloadManager завершает и обрыв, и неудачное подключение.
- Уведомление DownloadManager в шторке во время загрузки — «Gemma 4 E2B» с прогрессом; в паузе ожидания повтора его нет.
- Браузер (dev-сервер, Chrome): экран «Голос» показывает выбор модели, поле адреса и пояснение «Модель скачивается и работает только в Android-приложении», кнопок нет, ошибок в консоли нет.

Исправления по ревью скептика (`memory/findings_skeptic_model_download.md`), тот же эмулятор, 2026-11-21, протокол — `memory/progress_voice_model_download_fix.md`; для сравнения тем же способом проверялся APK до исправлений:
- Резервная копия при скачанной модели (`bmgr transport com.android.localtransport/.LocalTransport`, `bmgr backupnow`): до исправления — модель 2 588 148 224 байт в замере, «Transport quota exceeded», «Size quota exceeded», прежняя копия транспорта удалена; после — «Success», копия 4,5 МБ, в ней IndexedDB WebView (задачи) и `shared_prefs` без `model_downloader.xml`, из внешнего хранилища — ничего. Правила видны в APK: `aapt2 dump xmltree` манифеста — `fullBackupContent` и `dataExtractionRules`.
- «Отменить» сразу после успешного завершения (цикл на устройстве ждал статуса 200 в базе DownloadManager и нажимал кнопку): до исправления — файл удалён, «Не скачана»; после — файл на месте, «Скачана», сообщение «Gemma 4 E2B скачана», запись загрузки не удалена.
- Запись загрузки исчезла посреди скачивания (`pm clear com.android.providers.downloads` на 15 %, файл уже полного размера): экран «Не скачана», файл удалён как мусор. Очистка данных «Диспетчера загрузок» сами файлы не удаляет — проверено при скачанной модели.
- Обычная отмена на 10 % — «Загрузка отменена», каталог пуст; `http:/адрес` — «Неверный адрес сервера», загрузка не ставится.

### Тест-кейсы для проверки на телефоне
1. На компьютере: `env UID=$(id -u) GID=$(id -g) docker compose up -d model-server`; узнать адрес компьютера в сети (deployment.md). Телефон и компьютер — в одной сети Wi-Fi.
2. Настройки → Голос: выбрана «Gemma 4 E2B», «Не скачана».
3. Ввести `адрес:8088` → «Скачать» → прогресс в МБ и процентах на экране и в шторке; по окончании — «Скачана, 2,59 ГБ» и сообщение «Gemma 4 E2B скачана».
4. Свернуть приложение во время скачивания и вернуться — прогресс продолжается.
5. Закрыть приложение из «недавних» во время скачивания и открыть снова — экран показывает идущую загрузку.
6. Остановить раздачу (`docker compose stop model-server`) во время скачивания → «Нет связи с сервером…»; запустить (`docker compose start model-server`) — загрузка продолжается с того же места.
7. «Отменить» во время скачивания → «Не скачана», место освобождено (Настройки телефона → Приложения → Секретарь → Хранилище).
8. «Удалить модель» → «Не скачана», место освобождено.
9. Неверный адрес (`abc:99999`, `http:/адрес`) → сообщение об ошибке без загрузки; адрес без раздачи → «Нет связи с сервером, повтор через некоторое время»; до ошибки «Нет связи с сервером: проверьте адрес и что раздача запущена» — около 15–20 минут повторов, отменить можно сразу; верный адрес с лишним путём (`адрес:8088/x`) → «На сервере нет файла модели (HTTP 404)».
10. Открыть Настройки → Голос в браузере (PWA) → пояснение, что докачка только в Android-приложении.
11. Модель скачана → поставить новый APK поверх (тот же ключ, больший `versionCode`) → «Скачана, 2,59 ГБ», файл на месте.
12. Удалить приложение и поставить снова → «Не скачана», в Настройках телефона места под модель не занято (каталог удалён вместе с приложением).
13. Перезагрузить телефон посреди скачивания → после загрузки системы загрузка продолжается (видно в шторке), экран показывает прогресс.
14. Посреди скачивания выключить Wi-Fi (телефон уходит на мобильную сеть) → «Нет связи с сервером…» или «Ждёт подключения к сети»; включить Wi-Fi — загрузка продолжается.
15. Нехватка места: телефон с менее чем 2,6 ГБ свободного → ошибка «Недостаточно места на телефоне», экран «Не скачана».
16. Резервная копия при скачанной модели (компьютер с adb): `adb shell bmgr backupnow io.github.greatermagistr007.secretar` → «Success», а не «Size quota exceeded».

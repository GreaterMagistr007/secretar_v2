## Решения

### Р-1. Название проекта — Secretar
Причина: указание владельца 2026-09-13.

### Р-2. Проект делается с нуля; другие проекты источником не являются
Документация, решения и код других проектов, включая прежнюю версию «secretar», в этот проект не переносятся и при принятии решений не учитываются. Источник истины — только документация этого репозитория и прямые указания владельца.
Причина: указание владельца 2026-09-13.

### Р-3. MVP минимальный, функционал наращивается постепенно
В работу берётся только то, что можно сделать здесь и сейчас. Попытка охватить весь функционал сразу запрещена. Всё, что не входит, — в `backlog_post_mvp.md` с триггером возврата.
Причина: указание владельца 2026-09-13.

### Р-4. Первый этап — PWA-прототип
Начинаем с прототипа в виде PWA.
Причина: указание владельца 2026-09-13.

### Р-5. Стек не выбран, определяется по ходу разработки
Технологический gate открыт, см. `../tech_stack.md`. Единственное зафиксированное ограничение — PWA на первом этапе (решение Р-4).
Причина: указание владельца 2026-09-13 — определяться по ходу разработки, а не заранее.

### Р-6. Роль Claude — документация, агенты, проверка результатов
Зона ответственности Claude: чёткое ведение документации, создание агентов под задачи, постановка задач агентам, проверка результатов их работы на соответствие задаче и исходной просьбе владельца. Реализацию выполняют агенты; Claude правит сам только тривиальное.
Причина: указание владельца 2026-09-13. Детали — `../rules_work.md`.

### Р-7. Каждое действие записывается в документацию
Триггер выполнения = триггер фиксации. Недокументированной работы в проекте не существует.
Причина: указание владельца 2026-09-13.

### Р-8. Коммит и пуш по завершении каждого этапа — обязательны и без запроса
Переопределяет глобальное правило «push только по решению пользователя».
Причина: указание владельца 2026-09-13.

### Р-9. Чтение и правка файлов внутри каталога проекта — без запроса
Подтверждение сохраняется только для секретов, настроек самого Claude Code и разрушительных команд.
Причина: указание владельца 2026-09-13.

### Р-10. Документация и память проекта хранятся только в каталоге проекта
Вся документация (`docs/`) и вся память (`memory/`) лежат в директории проекта, коммитятся и пушатся. **Глобальная память Claude (`~/.claude/projects/...`) для информации этого проекта не используется вообще** — ни для заметок, ни для черновиков, ни для промптов сессий. Ничего существенного вне репозитория: ни в глобальной памяти, ни в локальных заметках вне проекта, ни в scratchpad сессии, ни в переписке. Актуально только запушенное.
Причина: указание владельца 2026-09-13; проект ведётся с нескольких устройств, и всё, что осталось вне репозитория, на другом устройстве не существует. Переопределяет глобальную инструкцию Claude Code о ведении памяти в `~/.claude/projects/.../memory/`.

### Р-11. Суть MVP — задачник с тремя экранами
«Секретарь» на этапе MVP: календарь (главная), экран задачи, настройки (одна настройка «тест настройки», bool). Одна сущность — задача, привязанная к дню, со свойствами описание, дата, регулярность, статус. Подробности — `../product_goals.md`, требования — `../req_tasks.md` и `../req_screens.md`.
Причина: указание владельца 2026-09-13.

### Р-12. Главная цель этапа — подобрать дизайн
Функциональный объём подчинён этой цели: берётся минимум, достаточный, чтобы оценить дизайн на реальных экранах. Скорость итерации важнее полноты функционала.
Причина: указание владельца 2026-09-13 — «сейчас делаем MVP и для нас ключевое — подобрать дизайн».

### Р-13. Форма поставки — PWA, размещение на GitHub Pages
Приложение делается как PWA и публикуется на GitHub Pages.
Причина: указание владельца 2026-09-13 — чтобы легко смотреть на телефоне и обновлять без магазинов приложений.

### Р-14. Стек — Vite + Svelte 5 + TypeScript
Состав, версии и отклонённые варианты — `../tech_stack.md`. Закрывает вопрос В-2 (технологический стек).
Причина: у Svelte самый лёгкий рантайм из зрелых вариантов и разметка, близкая к HTML, — при подборе дизайна (решение Р-12) переделка вёрстки дешевле, чем в JSX; Vite даёт статическую сборку под Pages и мгновенный dev-сервер. TypeScript берётся версии 6.x, потому что `svelte-check` объявляет peer `^5.0.0 || ^6.0.0` и с 7.x не совместим.

### Р-15. Хранилище — IndexedDB через Dexie, повторения не материализуются
Схема: таблица `tasks` (правило задачи) и таблица `completions` (отметки выполнения по паре «задача + день»). Индексы по дате, по регулярности и multiEntry по токенам описания. Повторения вычисляются на лету для видимого диапазона, а не сохраняются экземплярами. Подробности — `../architecture_storage.md`.
Причина: требования Т-7 (индексация по дате), Т-8 (производительность при росте базы) и Т-9 (хранение на устройстве); материализация повторений превращает одну ежедневную задачу в сотни строк в год, а IndexedDB даёт индексные диапазонные запросы, которых нет ни у localStorage, ни у хранения в одном JSON.

### Р-16. Отметка выполнения принадлежит конкретному повторению
Статус хранится парой «задача + дата повторения», а не полем задачи. Для задачи без повторений повторение одно — дата самой задачи, поэтому ветвлений в коде нет.
Причина: требование Т-5 (статус выполнения) — владелец задал, что у регулярной задачи выполненным считается только ближайшее повторение.

### Р-17. Окружение сборки — docker-контейнер
Сборка, dev-сервер и проверки идут в контейнере `node:22-alpine`, запуск через `docker compose`. Node на хосте (20.20.1) — запасной путь.
Причина: одинаковое поведение на всех устройствах разработки; Vite 8 требует Node `^20.19 || >=22.12`, и привязываться к версии, установленной на конкретной машине, нельзя.

### Р-18. Публикация на GitHub Pages выполняется в рамках проекта
Публикация — это пуш в `master`, дальше работает GitHub Actions. Глобальный запрет «Claude никогда не деплоит» относится к рабочим серверам Vigbo и на этот проект не распространяется. Разовую настройку в интерфейсе GitHub (публичность репозитория, включение Pages) делает владелец — у Claude нет доступа к настройкам репозитория.
Причина: прямое указание владельца 2026-09-13 «реализуем само PWA и выкладываем его на GitHub Pages»; Secretar — личный проект владельца, рабочих контуров не затрагивает.

### Р-19. Роутинг — хэш-based
Маршруты вида `#/calendar`, `#/task/:id`, `#/settings`; свой роутер на несколько десятков строк, без зависимости.
Причина: GitHub Pages не умеет rewrite — при обычных путях прямое открытие ссылки или обновление страницы даёт 404.

## Осознанные решения — не переоткрывать
Решения, принятые с известной ценой и закрытые для обсуждения. Пересмотр возможен единственным путём: владелец сам его поднимает.
- **Р-2 (проект с нуля, другие проекты не источник).** Цена известна: наработки прежней версии не переиспользуются, часть анализа делается заново.
- **Р-3 (минимальный MVP).** Цена известна: заметная часть желаемого функционала уезжает в бэклог и появится позже.
- **Р-10 (документация и память только в каталоге проекта).** Цена известна: глобальная память Claude не используется, всё ведётся в репозитории и требует коммита с пушем.
- **Р-12 (главная цель этапа — подобрать дизайн).** Цена известна: функционал наращивается медленно, часть возможностей появится заметно позже.
- **Р-15 (повторения не материализуются).** Цена известна: поиск с середины слова по индексу невозможен (позиция каталога 15), вхождения повторений вычисляются при каждом показе диапазона.

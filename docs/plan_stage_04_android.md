# План этапа 4: Android-приложение и уведомление

Поручение владельца 2026-11-21: обернуть приложение в APK, показывать неубираемое уведомление, пока на сегодня есть незавершённые задачи, переключатель — в «Настройки → Уведомления», по умолчанию включён; готовый APK отправить в Telegram. Решения: Р-20 (Capacitor), Р-30 (повторный показ при смахивании), Р-31 (будильник в полночь по списку на 60 дней), Р-32 (переключатель). Требования: Т-29, Т-30, Т-31.

## Шаги
1. **Сборка под Capacitor.** Вторая сборка Vite с относительным `base` для WebView (Pages-сборка не меняется: `base: '/secretar_v2/'`); service worker в нативной сборке не регистрируется — ассеты и так лежат в APK, а устаревший кэш SW мешал бы обновлениям.
2. **Проект `android/`** — `npx cap add android`, `appId` `io.github.greatermagistr007.secretar`, имя «Секретарь», иконка из имеющихся иконок PWA. Каталог `android/` коммитится, артефакты сборки — нет.
3. **Расчёт в веб-части** — чистый модуль: по задачам и отметкам число незавершённых задач на каждый день с сегодня на 60 дней вперёд (через существующий `occursOn`). Покрыт юнит-тестами без БД.
4. **Мост в нативную часть** — свой локальный плагин Capacitor `TaskNotifier` с методом `update({ enabled, counts })`. Веб-часть вызывает его при старте, при возврате в приложение, после создания задачи и смены отметки и при переключении настройки; смену суток отрабатывает нативный будильник по уже переданному списку (уточнено при реализации). В браузере вызов ничего не делает.
5. **Нативная часть (Java)** — хранит список в SharedPreferences, показывает или снимает уведомление `ongoing` с числом задач; `deleteIntent` → повторный показ; будильник на ближайшую полночь (`setAndAllowWhileIdle`, без точных будильников — задержка допустима; по факту система даёт окно до часа, см. mechanic_notifications.md «Известные границы»); восстановление будильника после `BOOT_COMPLETED`, `TIME_SET`, `TIMEZONE_CHANGED`; нажатие открывает приложение; запрос разрешения `POST_NOTIFICATIONS` (Android 13+). Чистая логика (разбор списка, выбор числа на дату, расчёт полуночи) — отдельным классом с JUnit-тестами.
6. **Экран «Уведомления»** — маршрут `#/settings/notifications`, кнопка на экране настроек, переключатель «Показывать push уведомление с задачами», по умолчанию включён, хранение по образцу выбора темы; в браузере — пояснение, что действует в Android-приложении; при отказе в разрешении — пояснение, как включить.
7. **Сборка APK в контейнере** — `Dockerfile.android` (JDK 21, Android SDK 36) и сервис в `docker-compose.yml`; подпись постоянным ключом `release.keystore`, пароли в `.env.android`, оба файла вне git. `versionCode` растёт с каждой выдачей.
8. **Проверка** — тесты, `svelte-check`, сборка Pages без изменений; APK на эмуляторе в контейнере (`/dev/kvm` есть): уведомление появляется, после смахивания возвращается, снимается при отметке всех задач, переключатель выключает, полночь — сдвигом времени эмулятора.
9. **Документация** — `mechanic_android.md` (упаковка и сборка), `mechanic_notifications.md` (уведомление), `deployment.md`, `tech_stack.md`, `INDEX.md`, хронология.

## Вне этапа
Перенос данных из браузера в APK (экспорт и импорт), публикация в Google Play, iOS, напоминания ко времени — в бэклог.

# Механика: всплывающее сообщение

Реализована 2026-11-21, этап 8 плана голосового управления ([plan_stage_05_voice.md](plan_stage_05_voice.md)). Решение Р-35 (успех 1 с + 2 с затухания, ошибка 4 с + 2 с; цвета из темы) — выбор владельца 8.б и 8.4. Первый вызывающий код — голосовой конвейер (следующие этапы); до него сообщение в интерфейсе не вызывается нигде.

## Views
- `src/lib/components/Toast.svelte` — монтируется один раз в `src/App.svelte` после `BottomNav`, поэтому переживает смену экранов.
- Контейнер `div.region` с `aria-live="polite"` всегда в DOM: диктор озвучивает изменения только внутри области, существовавшей до них. У сообщения об ошибке `role="alert"`, у успеха роли нет.
- Сообщение пересоздаётся по номеру показа (`{#key id}`): анимация начинается заново и при повторе того же текста.
- Вид: фон `--color-surface`, текст `--color-text`, скругление `--radius-md`, тень `--shadow-card` плюс мягкая тень. Тип — значком (галочка / «!» в круге) и полосой слева 4px: успех `--color-primary`, ошибка `--color-weekend` (цвет ошибок по всему проекту). Новых токенов в темах нет; контраст фона и текста уже проверен по темам (решение Р-26).
- Место: `position: fixed`, по центру; поля слева и справа `--space-md` + `safe-area`, длинный текст переносится (`overflow-wrap: anywhere`). Низ — над рядом кнопки «+» экрана календаря: `--space-md + --nav-height + safe-area-inset-bottom + 56px` (высота «+») `+ --space-sm`. Проверено на 360 px: сообщение 16…344 px, зазор до «+» 10 px, навигацию и «+» не перекрывает.
- `z-index: 60` — выше навигации (20), «+» (30), оверлея (40) и модалки создания задачи (50). `pointer-events: none` — сообщение не мешает касаниям.
- Анимация: `@keyframes toast-fade-success` (непрозрачно до 33,333 %, затем линейно к 0) и `toast-fade-error` (до 66,667 %); длительность — инлайн-переменная `--toast-duration` из `toastDuration()`. Доли продублированы из `TOAST_TIMING` — меняются вместе. Из DOM сообщение убирает таймер логики, а не `animationend`.
- Имя анимации задаётся прямо в классах `.toast--success` / `.toast--error`, а не через CSS-переменную: Svelte переименовывает `@keyframes` компонента в `svelte-<хэш>-…` и переписывает имя только в свойствах `animation*`. Через переменную затухания не было (найдено при визуальной проверке 2026-11-21).
- `prefers-reduced-motion: reduce` — `animation: none`: сообщение видно всё время показа и затем снимается.

## Сервисы
- `src/lib/toast.ts` — чистая логика без рун и DOM:
  - `TOAST_TIMING` — длительности по типам: `success` 1000 + 2000 мс, `error` 4000 + 2000 мс; `toastDuration(type)` — сумма (3000 / 6000 мс).
  - `createToastController(onChange, schedule?)` — `show(type, text)` сразу отдаёт новое сообщение в `onChange`, отменяет таймер снятия прежнего и ставит свой на `toastDuration(type)`; по таймеру `onChange(null)`. Номер показа `id` растёт с каждым вызовом.
  - `Schedule` — внедряемый таймер `(callback, ms) => cancel`; по умолчанию `setTimeout`.
- `src/lib/toast.svelte.ts` — руна `$state` поверх контроллера: `toast.current` для компонента и `showToast(type, text)` — публичный вызов для остального приложения.

## API
`showToast(type: 'success' | 'error', text: string): void` из `src/lib/toast.svelte.ts`. Новое сообщение заменяет текущее сразу; текст собирает вызывающий код (решение по этапу 7.1), пустой текст не отсекается.

## Примечания
- Тесты: `src/lib/toast.test.ts`, 16 тестов, данные — литералы. Пограничные значения: снятие на 2999/3000 мс (успех) и 5999/6000 мс (ошибка), ошибка не снимается на сроке успеха, замена посреди показа (прежний таймер не снимает новое, срок берётся по типу нового), повтор того же текста (новый `id`, срок заново), показ после снятия, внедрённый таймер (срок и отмена при замене). Покрытие `toast.ts` — 100 % (файл в `coverage.include`). Мутации «без отмены прежнего таймера», «срок на 1 мс меньше», «id не растёт», «не обнуляется отмена после снятия» — все ловятся.
- Визуальная проверка 2026-11-21 (Chrome, dev-сервер, 360 px, темы v09 светлая и v05 тёмная): снятие из DOM на 3001 / 6000 мс, замена ошибки успехом в 2002 мс — снятие в 5001 мс; ключевые кадры и длительность подтверждены через Web Animations API. `prefers-reduced-motion` живьём не эмулировался — проверены наличие и порядок правила.
- Вызов из консоли dev-сервера: `const m = await import('/secretar_v2/src/lib/toast.svelte.ts'); m.showToast('error', '…')`. Если файл менялся при запущенном dev-сервере, приложение держит модуль с меткой `?t=<HMR>` и импорт без метки даёт второй экземпляр; адрес, который загрузило приложение, — в `performance.getEntriesByType('resource')`.
- Логов нет: модуль ничего не делает, кроме показа; диагностика — в вызывающем коде (этап 9 плана).

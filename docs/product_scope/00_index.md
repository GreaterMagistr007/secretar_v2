# Каталог функционала — индекс

Единственный источник состава MVP — **колонка «Приоритет»** в таблице ниже. Любой другой перечень является пересказом и при расхождении уступает ей. Числа состава здесь намеренно не приводятся: продублированная цифра разойдётся при первой же правке.

## Правила ведения
1. Шкала приоритета закрытая: `MVP` · `post-MVP` · `отложено` (с триггером возврата в [../backlog_post_mvp.md](../backlog_post_mvp.md)) · `не-цель`. Значений «требует решения» и «частично» не существует.
2. Номер позиции — постоянный идентификатор, не переиспользуется; номера удалённых позиций остаются свободными.
3. Одна строка — один функционал.
4. Строк-отказов в таблице нет: отклонённое живёт в разделе «Рассмотрено и отклонено».
5. Обязательство, найденное в тексте документации, обязано иметь строку каталога — иначе оно теряет владельца и исчезает при переходе к требованиям.
6. Закрытый перечень (состав экранов, значения регулярности, состав настроек) пополняется только правкой позиции-носителя, а не упоминанием в другой позиции.
7. Отмена ранее принятого решения фиксируется явно: «прежнее решение <какое> отменено, причина <какая>».
8. Ссылаться на позицию только с расшифровкой: «позиция 3 (экран задачи)».

## Обязательные проверки после любой правки
```
F=docs/product_scope/00_index.md
grep -c '^| [0-9]' $F                                        # число позиций
awk -F'|' '/^\| [0-9]/ && $4 ~ /^ *MVP *$/' $F | wc -l       # число позиций MVP
awk -F'|' '/^\| [0-9]/ {print $2+0}' $F | sort -n -c && echo "номера возрастают"
```
Проверки считают только строки таблицы (начинаются с `| ` и цифры) и сравнивают номера численно: строковая сортировка ставит 10 перед 9 и даёт ложную тревогу.

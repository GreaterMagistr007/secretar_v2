# Цели проекта Secretar

## Суть
«Секретарь» — личное приложение-задачник. На текущем этапе MVP: задачи привязаны к конкретному дню, есть календарь, экран задачи, настройки и выбор темы (состав — ниже, в разделе «Состав MVP»; он и есть единственное место перечня). Развитие функционала — постепенное, только тем, что можно сделать здесь и сейчас (решение Р-3 — минимальный MVP).

## Главная цель этапа MVP: подобрать дизайн
Ключевое для владельца сейчас — **подобрать дизайн**, а не набрать функционал. Отсюда следует всё остальное:
- приложение делается как **PWA**, чтобы смотреть его на телефоне без установки из магазинов и обновлять мгновенно (решение Р-13);
- функциональный объём минимален — ровно столько, чтобы дизайн можно было оценить на реальных экранах;
- скорость итерации важнее полноты: правка → пуш → обновление на телефоне.

## Состав MVP
Четыре экрана:
1. **Календарь** — главная страница. Разработан первым.
2. **Экран задачи** — просмотр одной задачи: текст, дата, приоритет, повторение. Редактирования нет (требование Т-28), отметки выполнения здесь тоже нет (решение Р-29) — она ставится в списке задач дня.
3. **Настройки** — кнопка «Выбор темы» (требование Т-19). Прежняя редакция «одна настройка „тест настройки“, bool» отменена 2026-09-13 вместе с требованием Т-12.
4. **Выбор темы** — экран со всеми вариантами оформления (требования Т-20…Т-22, позиция каталога 27).

Сущность одна — задача, привязанная к дню, со свойствами: описание, дата, приоритет, регулярность, статус выполнения по конкретному повторению. Требования — [req_tasks.md](req_tasks.md), экраны — [req_screens.md](req_screens.md), каталог функционала — [product_scope/00_index.md](product_scope/00_index.md).

## Аудитория
Владелец проекта — единственный пользователь на этапе MVP. Устройство наблюдения — телефон, браузер; десктоп — для разработки.

## Ценность
Задачи с регулярным повторением, доступные офлайн на телефоне, без регистрации и без сервера: данные лежат на устройстве.

## Не-цели этапа MVP
Явно **не делаем** и в этот объём не берём:
- сервер, аккаунты, авторизацию, синхронизацию между устройствами;
- уведомления и напоминания;
- совместную работу, обмен задачами;
- интеграции с внешними календарями;
- ИИ-функции;
- нативные клиенты под Android и iOS.
Всё это при появлении повода уходит в [backlog_post_mvp.md](backlog_post_mvp.md) с триггером возврата, а не в текущий объём.

## Критерии успеха этапа
1. PWA открывается на телефоне по ссылке, ставится на домашний экран, работает офлайн.
2. Обновление доставляется пушем в репозиторий без действий на устройстве, кроме перезагрузки страницы.
3. На экранах видно дизайн, по которому владелец может судить и вносить правки.
4. Хранение задач не тормозит при росте базы: поиск по описанию и выборка по дате идут по индексам (см. [architecture_storage.md](architecture_storage.md)).

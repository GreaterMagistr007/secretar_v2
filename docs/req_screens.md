# Требования: экраны

Требования Т-10…; сквозная нумерация общая с [req_tasks.md](req_tasks.md). Ссылаться только с расшифровкой: «требование Т-12 (экран настроек)».

## Т-10. Состав экранов MVP
Ровно три экрана: **Календарь** (главная), **Экран задачи**, **Настройки**. Четвёртого экрана в MVP нет.
Источник: указание владельца 2026-09-13.

## Т-11. Экран «Календарь» — главный
Главная страница приложения. Разрабатывается первым из трёх.
Состав, виды (месяц, неделя, день), маршрут создания задачи из календаря — владелец задаёт отдельно, вопрос В-6 (маршрут создания задачи из календаря) и вопрос В-7 (устройство экрана календаря). До ответа экран не проектируется.
Источник: указание владельца 2026-09-13.

## Т-12. Экран «Настройки» (редакция отменена)
Прежняя редакция: единственная настройка «тест настройки» со значением bool. **Отменена 2026-09-13**, причина — владелец заменил тестовую настройку на кнопку выбора темы. Действующая редакция — требование Т-19 (экран «Настройки» — кнопка выбора темы).

## Т-13. Экран задачи
Просмотр и редактирование одной задачи; свойства — по [req_tasks.md](req_tasks.md): описание, дата, регулярность, статус.
Детали компоновки задаёт владелец при подборе дизайна.
Источник: указание владельца 2026-09-13.

## Т-14. Название приложения — «Секретарь»
Название приложения в манифесте PWA, в заголовке страницы и на домашнем экране устройства — **«Секретарь»** (русскими буквами).
Источник: указание владельца 2026-09-13.

## Т-15. Стартовый экран первой поставки
Первая поставка — оболочка PWA: главный экран с надписью **«Секретарь»**. Функционала задач в ней ещё нет; её задача — проверить, что PWA ставится на телефон, открывается и обновляется.
Источник: указание владельца 2026-09-13.

## Т-16. Приложение устанавливается как PWA
Манифест, иконки, service worker; установка на домашний экран телефона; работа офлайн после первой загрузки; обновление доставляется после публикации без переустановки.
Источник: указание владельца 2026-09-13 (PWA выбрана ради просмотра на телефоне и лёгкого обновления).

## Т-17. Язык интерфейса — русский
Все подписи, кнопки и сообщения — на русском.
Источник: указание владельца 2026-09-13, из формулировок задания.

## Т-18. Нижнее навигационное меню на всех экранах
Внизу каждого экрана — панель навигации из двух вкладок: **Календарь** (значок календаря) и **Настройки** (значок шестерёнки). В каждой вкладке сначала значок, под ним название. Активная вкладка выделена цветом темы.
Источник: указание владельца 2026-09-13.

## Т-19. Экран «Настройки» — кнопка выбора темы
На экране настроек одна кнопка — **«Выбор темы»**, она открывает экран выбора темы (требование Т-20).
Источник: указание владельца 2026-09-13. **Отменяет прежнюю редакцию требования Т-12** (единственная настройка «тест настройки» со значением bool): тестовая настройка была заглушкой до появления настоящей, теперь её место занял выбор темы.

## Т-20. Экран выбора темы
Показывает все варианты оформления так же, как демо-страница галереи: превью каждого макета сеткой. Клик по варианту **применяет его тему ко всему приложению целиком**, а не открывает макет. Выбранный вариант отмечен **большой зелёной галочкой**.
Источник: указание владельца 2026-09-13.

## Т-21. Тема запоминается между запусками
Выбранная тема сохраняется на устройстве и восстанавливается при следующем открытии приложения — в том числе после полного закрытия.
Источник: указание владельца 2026-09-13.

## Т-22. Тема применяется ко всему приложению
Смена темы перекрашивает все экраны: календарь, настройки, выбор темы, нижнюю навигацию, кнопки и модалки. Жёстко прописанных цветов в экранах нет — только токены темы (см. [design_tokens.md](design_tokens.md)).
Источник: указание владельца 2026-09-13.

## Т-23. Ключевые стилевые решения вынесены в переменные
Оформление каждого варианта описывается закрытым набором именованных токенов: главный, вторичный и третичный цвета, основная и второстепенная кнопки, поверхности, текст, границы, состояния календаря, скругления, тени, типографика, оформление навигации. Состав набора — [design_tokens.md](design_tokens.md).
Источник: указание владельца 2026-09-13.

## Т-25. Кнопка добавления задачи
На экране «Календарь» — круглая кнопка с символом «+» в правом нижнем углу, над нижней навигацией. Клик открывает модалку создания задачи (требование Т-26).
Источник: указание владельца 2026-09-15.

## Т-26. Модалка создания задачи
Форма из четырёх полей:
- **Текст** — обязательное, по умолчанию поле пустое;
- **Дата** — обязательное, по умолчанию сегодняшний день; если в календаре выбран день, то выбранный;
- **Приоритет** — обязательное, по умолчанию «Средний»;
- **Повторение** — по умолчанию «Без повторений», значение выбрано всегда.
Сохранение недоступно, пока не заполнено хотя бы одно из трёх обязательных полей. Повторение пустым быть не может и на доступность кнопки сохранения не влияет. Закрытие модалки — по фону, по Esc и по кнопке отмены; введённое при закрытии не сохраняется.
Источник: указание владельца 2026-09-15; поле «Повторение» добавлено 2026-09-27 как способ задать регулярность по требованию Т-4 — прежняя редакция «форма из трёх полей, все обязательные» отменена.

## Т-27. Список задач выбранного дня
Клик по дате в календаре выбирает день; под календарём появляется список задач этого дня. Пока день не выбран, списка нет. У каждой строки списка есть флажок выполнения: он относится к этому дню, а не ко всей задаче (требование Т-5, решение Р-29). Выполненная задача остаётся на своём месте, её текст зачёркнут.
Источник: указание владельца 2026-09-15; флажок выполнения добавлен 2026-09-27 вместе с требованием Т-5.

## Т-28. Полноэкранный просмотр задачи
Клик по задаче в списке открывает её на весь экран: виден полный текст задачи, дата, приоритет и повторение. Отметки выполнения на этом экране нет — адрес `#/task/<id>` не несёт даты повторения (решение Р-29).
Источник: указание владельца 2026-09-15; строка повторения добавлена 2026-09-27.

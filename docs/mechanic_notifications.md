# Механика: уведомление о незавершённых задачах дня

Реализована 2026-11-21, этап 4 ([plan_stage_04_android.md](plan_stage_04_android.md)). Закрывает требования Т-30 (раздел «Уведомления» в настройках) и Т-31 (постоянное уведомление) по решениям Р-30 (повторный показ смахнутого), Р-31 (будильник в полночь по списку на 60 дней) и Р-32 (переключатель, по умолчанию включён). Упаковка в APK — [mechanic_android.md](mechanic_android.md).

Уведомление локальное: сервер, FCM и любой push-сервис не участвуют.

## Модели
- Веб-часть: `localStorage`, ключ `secretar.notifications`. Значение `off` — пункт выключен; любое другое и отсутствие записи — включён (решение Р-32: по умолчанию включён).
- Нативная часть: `SharedPreferences` с именем `task_notifier`: `enabled` (boolean, по умолчанию `false` — пока веб-часть ни разу не передала состояние, уведомления нет) и `counts` — список «`YYYY-MM-DD=число`» построчно.

## Views
- `src/routes/SettingsScreen.svelte` — под кнопкой «Выбор темы» кнопка «Уведомления».
- `src/routes/NotificationsScreen.svelte` — заголовок со стрелкой «назад» (как на экране выбора темы), переключатель `<input type="checkbox" role="switch">` «Показывать push уведомление с задачами». Переключение: запомнить → если включён, а разрешения нет — запросить его → пересчитать уведомление. Пояснения под переключателем:
  - в браузере — пункт действует в Android-приложении, в браузере уведомление не показывается;
  - в приложении при включённом пункте и отказе в разрешении (`denied` или `prompt-with-rationale`) — как включить: «Настройки телефона → Приложения → Секретарь → Уведомления → разрешить». При возвращении на экран (`visibilitychange`) разрешение перечитывается, и пояснение исчезает, если уведомления разрешили.

## Сервисы

### Расчёт — `src/lib/notification-counts.ts`
Чистые функции, покрыты тестами `notification-counts.test.ts`:
- `HORIZON_DAYS = 60` — горизонт списка (решение Р-31);
- `horizonDates(today, days)` — дни горизонта начиная с сегодня; следующий день строится конструктором `Date` из локальных полей и превращается в строку тоже по локальным полям (`toIsoDate`), поэтому дни перевода часов дату не сдвигают. Блок тестов «в восточной зоне» временно ставит `process.env.TZ = 'Europe/Moscow'` (Node применяет его сразу, зона стенда America/New_York возвращается после каждого теста): в западной зоне стенда подмена `toIsoDate` на `toISOString().slice(0, 10)` не видна, в UTC+3 она сдвигает горизонт на сутки назад — проверено мутацией;
- `countPendingByDay(occurrences, dates)` — число вхождений с `done === false` на каждый день из `dates`, в том же порядке; день без незавершённых задач — `0`.

Вхождения берутся существующим `listOccurrencesByRange(сегодня, сегодня + 59)`: он разворачивает повторения через `occursOn` и проставляет отметки по конкретному дню (требования Т-4, Т-5), отдельной логики повторений здесь нет.

### Мост — `src/lib/task-notifier.ts`
Покрыт тестами `task-notifier.test.ts`; `@capacitor/core` и `task-repository` в них подменены, база не открывается.
- `registerPlugin<TaskNotifierPlugin>('TaskNotifier')` — интерфейс плагина: `update({ enabled, counts })`, стандартные `checkPermissions()` и `requestPermissions()` с псевдонимом `notifications`.
- `isNotifierAvailable()` — `Capacitor.isNativePlatform()`. В браузере ни одна функция плагин не вызывает: у плагина нет веб-реализации, и вызов в браузере отклонился бы.
- `loadNotificationsEnabled()` / `saveNotificationsEnabled()` — по образцу `saveThemeId`/`loadThemeId`: каждое обращение к `localStorage` в `try/catch`, недоступное хранилище читается как «включён».
- `refreshTaskNotification()` — читает настройку, при включённом пункте считает числа на 60 дней и вызывает `update`; при выключенном передаёт `{ enabled: false, counts: [] }` без чтения задач. Вызовы выстраиваются в очередь (`queue = queue.then(...)`): две передачи подряд иначе могли бы завершиться в обратном порядке и оставить нативной части устаревшие числа. Ошибки пишутся в `console.error` и не всплывают — сохранение задачи от уведомления не зависит.
- `checkNotificationPermission()` / `requestNotificationPermission()` — состояние разрешения; `null` в браузере.
- `startTaskNotifier()` — при старте: если пункт включён и разрешение ещё ни разу не спрашивали (`prompt`) — системный диалог; затем передача. Подписка на `visibilitychange`: каждое возвращение в приложение пересчитывает. Возвращает функцию отписки для `$effect`.

### Когда веб-часть передаёт числа
| Повод | Где |
|---|---|
| Старт приложения | `App.svelte`: `$effect(() => startTaskNotifier())` |
| Возвращение в приложение (в том числе на следующий день) | `startTaskNotifier`, событие `visibilitychange` |
| Создание задачи | `CalendarScreen.svelte`, `createTask` после успешного `create` |
| Смена отметки выполнения | `CalendarScreen.svelte`, `toggleCompletion` после успешного `setCompleted` |
| Переключение пункта | `NotificationsScreen.svelte`, `toggle` |

Мутации задач в интерфейсе есть только эти две — `update` и `remove` хранилища экранами не вызываются (правка и удаление — вопрос В-14). Появятся — рядом с ними нужен тот же вызов `refreshTaskNotification()`. Обёртка хранилища, перехватывающая все записи, отвергнута: восемь методов делегирования ради двух мест вызова.

**Смена суток при открытом приложении** отдельного таймера в веб-части не имеет: число на новый день нативная часть выбирает сама по будильнику полуночи из уже переданного списка, а веб-часть продлевает горизонт при следующем возвращении в приложение или следующей записи. Горизонт при этом короче 60 дней ровно на число суток, проведённых без единого возвращения в приложение.

### Нативная часть — `android/app/src/main/java/io/github/greatermagistr007/secretar/`
- `TaskCounts` — чистая логика без Android API, покрыта JUnit-тестами `android/app/src/test/.../TaskCountsTest.java` (прогоняются задачей `test` в сборке APK):
  - `isValid(date, count)` — дата по шаблону `\d{4}-\d{2}-\d{2}`, число не отрицательное;
  - `serialize` / `parse` — формат хранения; испорченные строки при разборе пропускаются;
  - `countFor(counts, date)` — число на день, вне списка `0`;
  - `countToShow(enabled, stored, millis, zone)` — решение «какое число показывать»: при включённом пункте число на сегодня (день момента в поясе устройства) из строки хранения, при выключенном `0`; `0` — уведомления нет. Тесты: выключено (даже при числе на сегодня), включено без записи (`""` и `null`), число на сегодня в Москве и Нью-Йорке для одного момента, сегодня `0`, битая строка;
  - `dateKey(millis, zone)` — день момента в часовом поясе устройства;
  - `nextMidnight(millis, zone)` — начало следующих суток через `Calendar.add(DAY_OF_MONTH, 1)`, а не «+24 часа»: в дни перевода часов сутки длятся 23 или 25 часов;
  - `title(count)` — «Незавершённых задач на сегодня: N» (число через двоеточие, без склонения).
- `TaskNotifierPlugin` — плагин Capacitor `TaskNotifier`, зарегистрирован в `MainActivity` до `super.onCreate`. `update`: разбирает `counts` (пропуская невалидные пары), сохраняет `enabled` и список в `SharedPreferences`, вызывает `TaskNotifierReceiver.refresh`. Разрешение `POST_NOTIFICATIONS` объявлено под псевдонимом `notifications`; на Android 12 и ниже `checkPermissions`/`requestPermissions` переопределены и отвечают `granted` или `denied` по `areNotificationsEnabled()` — runtime-разрешения там нет.
- `TaskNotifierReceiver` — один приёмник на все поводы; на любой из них вызывает `refresh(context)` (`static synchronized`: его вызывают поток плагинов Capacitor из `update` и главный поток из приёмника — без блокировки вызов со старыми числами мог бы выполнить `notify` последним):
  - `TaskCounts.countToShow(...)` > 0 → показать или обновить уведомление, иначе снять (`cancel`);
  - пункт включён → будильник на ближайшую полночь `setAndAllowWhileIdle(RTC_WAKEUP, ...)`, выключен → будильник отменить.

Уведомление: канал `pending_tasks` «Задачи на сегодня» с `IMPORTANCE_LOW` (без звука и баннера), `setOngoing(true)`, `setOnlyAlertOnce(true)`, `setSilent(true)`, `PRIORITY_LOW`, без времени. Нажатие — `PendingIntent` на `MainActivity` (открывает приложение). `deleteIntent` — broadcast `RESHOW` в тот же приёмник: смахнутое уведомление показывается снова (решение Р-30). Перед `notify` — проверка разрешения (Android 13+) и `areNotificationsEnabled()`; без разрешения уведомление молча не показывается, будильник всё равно ставится — после выдачи разрешения уведомление появится при следующем пересчёте.

Манифест: приёмник `TaskNotifierReceiver` с `exported="false"` и фильтром `BOOT_COMPLETED`, `TIME_SET`, `TIMEZONE_CHANGED`, `MY_PACKAGE_REPLACED` — системные рассылки доходят и до неэкспортированного приёмника (так же объявлен `RescheduleReceiver` в WorkManager), а чужие приложения вызвать его не могут. `MY_PACKAGE_REPLACED` — сверх плана: APK ставится поверх прежнего, и без этого повода уведомление после обновления не вернулось бы до открытия приложения. Разрешения: `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`. Точные будильники (`SCHEDULE_EXACT_ALARM`) не запрашиваются.

## Примечания

### Известные границы
- **Android 14+ позволяет смахнуть даже `ongoing`-уведомление**, поэтому неубираемость держится повторным показом через `deleteIntent` (решение Р-30). На экране блокировки Android 14 `ongoing` по-прежнему не смахивается.
- **Будильник неточный**: `setAndAllowWhileIdle` срабатывает и в режиме Doze, но система ставит его с окном до часа — на эмуляторе Android 15 `dumpsys alarm` при каждой обычной постановке показывал `origWhen=... 00:00:00.000 window=+1h0m0s0ms`. Число в шторке может смениться в любой момент между 00:00 и примерно 01:00, а до этого показывает прежний день; у приложения в корзинах App Standby `rare`/`restricted` (Android 9+/12+; реально для приложения, которое открывают только через уведомление) — ещё позже, вплоть до часов. Точные будильники требуют отдельного разрешения (`SCHEDULE_EXACT_ALARM`) и сознательно не используются.
- **Горизонт 60 дней**: если приложение не открывать дольше 60 дней, список закончится, и уведомление перестанет появляться (день вне списка — ноль) до следующего открытия.
- **Данные APK отдельны от браузера**: уведомление считает только задачи, созданные в самом Android-приложении.
- **Без разрешения уведомлений нет**: на Android 13+ при отказе экран «Уведомления» объясняет, как включить; повторный системный диалог на старте не показывается.
- **Принудительная остановка** приложения (Настройки → Приложения → Секретарь → «Остановить»; у части производителей, например Xiaomi и Huawei, так же действует смахивание из «недавних») снимает и будильник, и само уведомление до следующего открытия приложения; `deleteIntent` в остановленное приложение не доставляется — так устроен Android.
- **Отключённый пользователем канал** «Задачи на сегодня» (долгое нажатие на уведомление → «Отключить»): уведомления нет, а экран «Уведомления» об этом не сообщает — разрешение при этом выдано и `areNotificationsEnabled()` отвечает `true`, `notify` в заблокированный канал система молча отбрасывает. Вернуть — в настройках уведомлений приложения.
- **Отдельного пересчёта при смене суток в веб-части нет**: число на новый день выбирает нативный будильник полуночи из уже переданного списка, горизонт продлевается при возвращении в приложение и при записи — см. «Смена суток при открытом приложении».

### Проверка на эмуляторе
2026-11-21, Android 15 (SDK 35, `google_apis` x86_64, пояс Europe/Moscow), подробный протокол — [memory/findings_android_emulator.md](../memory/findings_android_emulator.md). Пройдены: установка и системный диалог разрешения; без задач уведомления нет; появление и обновление числа при создании и отметке задач; смахивание — возврат без звука и баннера; переключатель на экране «Уведомления»; полночь при закрытом приложении (будильник и `TIME_SET`, переводом часов); ежедневная задача через полночь; перезагрузка (`BOOT_COMPLETED`); нажатие открывает приложение; смена пояса (`TIMEZONE_CHANGED`); отказ в разрешении и пояснение; установка поверх тем же APK (`MY_PACKAGE_REPLACED`). Не проверено: Android 14 и Android 12 и ниже (смахивание `ongoing` на 14, ветка разрешений до 13), режим Doze, настоящая полночь без перевода часов (на эмуляторе будильник срабатывал через ~22 с после 00:00 только потому, что часы переводились за 30 с до полуночи), экран блокировки, обновление на APK с большим `versionCode`.

### Тест-кейсы для проверки на устройстве или эмуляторе
1. Есть незавершённая задача на сегодня → в шторке уведомление «Незавершённых задач на сегодня: N».
2. Смахнуть уведомление → появляется снова, без звука и вибрации.
3. Отметить все задачи дня → уведомление снимается; снять отметку → возвращается.
4. Выключить пункт на экране «Уведомления» → уведомление снимается; включить → возвращается.
5. Перевести часы на следующий день (или дождаться полуночи) при закрытом приложении → число соответствует новому дню.
6. Перезагрузить телефон → уведомление на месте, будильник восстановлен.
7. Нажать на уведомление → открывается приложение.
8. Android 13+: отказать в разрешении → на экране «Уведомления» пояснение, как включить.
9. В браузере экран «Уведомления» показывает пояснение, что пункт действует в Android-приложении.

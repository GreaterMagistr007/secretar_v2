# Механика: задачи

Реализована 2026-09-15. Закрывает требования Т-1 (привязка к дню), Т-2 (текст обязателен), Т-3 (дата), Т-24 (приоритет), Т-25 (кнопка добавления), Т-26 (модалка создания), Т-27 (список задач дня), Т-28 (полноэкранный просмотр) и позиции каталога 29–32. Модель хранения — [architecture_storage.md](architecture_storage.md).

## Модели
`src/lib/tasks/types.ts` — контракт, единственный источник формы данных:
- `Task`: `id` (UUID v7), `text`, `date` (`YYYY-MM-DD`, плавающая), `priority` (`low` | `medium` | `high`), `recurrence` (пока всегда `none`), `searchTokens`, `createdAt`, `updatedAt`.
- `NewTask` — то, что вводит пользователь: текст, дата, приоритет.
- `TaskRepository` — интерфейс хранилища: `create`, `listByDate`, `listByRange`, `get`, `update`, `remove`, `search`.
- `DEFAULT_PRIORITY` = `medium`, `PRIORITY_LABELS` — подписи «Средний», «Низкий», «Высокий».

Слой доступа описан интерфейсом намеренно: юнит-тесты работают с реализацией в памяти и не открывают ни одного соединения с базой — правило проекта о тестах без БД.

Поле `recurrence` заведено сразу со значением `none`, хотя в форме не показывается: требование Т-4 (регулярность) остаётся в MVP, и менять схему задним числом дороже, чем завести поле сейчас.

## Миграции
Схема Dexie версии 1, таблица `tasks`: `id, date, priority, [priority+date], *searchTokens, updatedAt`. Имя базы — `secretar`. Применённые версии не редактируются: повторения и отметки выполнения добавят версию 2.

## Маршруты
`#/task/<id>` — полноэкранный просмотр задачи (требование Т-28). Роутер разбирает параметр, `router.hrefTask(id)` строит ссылку. Переход сделан обычной ссылкой, поэтому кнопка «назад» в браузере и жест возврата работают штатно.

## Views
- `src/routes/CalendarScreen.svelte` — сетка месяца, метки по реальным задачам диапазона (`listByRange` на все шесть недель сетки, по одной точке на каждый встретившийся приоритет), выбор дня, круглая кнопка «+» в правом нижнем углу над навигацией с учётом безопасных зон, список задач выбранного дня, легенда приоритетов.
- `src/lib/components/TaskCreateModal.svelte` — форма создания: текст (пустой), дата (сегодня или выбранный в календаре день), приоритет (по умолчанию «Средний», чипы с цветной точкой). Кнопка сохранения недоступна, пока хотя бы одно поле пустое; ошибки по-русски у поля; закрытие по фону, Esc и «Отмена»; ловушка Tab внутри модалки и возврат фокуса на кнопку «+».
- `src/lib/components/DayTaskList.svelte` — список дня: цветная метка приоритета, текст одной строкой с многоточием, подпись приоритета; пустое состояние «На этот день задач нет».
- `src/routes/TaskScreen.svelte` — просмотр: полный текст с переносами (`pre-wrap`, `overflow-wrap: anywhere`), дата, приоритет, закрытие ссылкой и по Esc.

## Сервисы
- `src/lib/tasks/id.ts` — UUID v7: 48 бит метки времени, версия и вариант по RFC, остальное из `crypto.getRandomValues`. Монотонность внутри миллисекунды — счётчиком в `rand_a`; при переполнении и при переводе часов назад метка берётся на миллисекунду вперёд, порядок не ломается.
- `src/lib/tasks/text.ts` — нормализация (нижний регистр, `ё` → `е`) и токенизация под поиск.
- `src/lib/tasks/validate.ts` — проверка формы: непустой текст, существующая дата, приоритет из перечня. Возвращает размеченное объединение, а не бросает исключения; собирает все ошибки сразу. Дата разбирается вручную, потому что `new Date('2026-02-31')` молча даёт 3 марта.
- `src/lib/tasks/sort.ts` — порядок в списке дня: высокий приоритет, средний, низкий; внутри — по времени создания.
- `src/lib/tasks/memory-repository.ts` — реализация в памяти (тесты и эталон поведения).
- `src/lib/tasks/dexie-repository.ts` — реализация поверх IndexedDB.
- `src/lib/tasks/repository.ts` — фабрика; `src/lib/task-repository.ts` — единственный экземпляр на приложение, чтобы экраны не открывали по соединению каждый.
- `src/lib/date.ts` — плавающие даты и их форматирование; `src/lib/priority.ts` — соответствие приоритета токену цвета; `src/lib/calendar-state.svelte.ts` — показываемый месяц и выбранный день вне компонента.

## Примечания

### Тесты
110 тестов в пяти файлах, все зелёные; покрытие тестируемых модулей 100 % по строкам, ветвям и функциям. Данные — литералы прямо в тестах. Проверено, что ни один тест не обращается к базе: `grep` по `Dexie` и `indexedDB` в тестах пуст. `dexie-repository.ts` не покрыт сознательно — это и есть слой доступа к базе, а автотесты проекта к базам не обращаются; его работа проверяется запуском приложения.

### Что проверено в браузере
Прогон на локальном сервере: кнопка «+» открывает модалку; поля по умолчанию — текст пустой, дата сегодняшняя (`2026-09-15`), приоритет `medium`; кнопка сохранения заблокирована при пустом тексте и разблокируется после ввода; после сохранения модалка закрывается, а в ячейке дня появляется метка и подпись «задач: 1»; клик по дню открывает список, клик по задаче ведёт на `#/task/<id>` с полным текстом, датой и приоритетом; «назад» в браузере и Esc возвращают на календарь; после перезагрузки страницы задача на месте (база `secretar`), а пустой день показывает «На этот день задач нет».

### Расхождение документации, устранённое по ходу
`architecture_storage.md` писался до реализации и описывал поле `description` и индексы по `recurrence`. Фактически поле называется `text` (так в контракте и в интерфейсе), а индексы заведены по `priority`: повторений ещё нет, индекс без запросов к нему только замедляет запись. Документ приведён к факту.

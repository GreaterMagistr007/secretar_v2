# Документация Secretar — индекс

Здесь всё, что нужно для понимания проекта и работы с ним. Временная память Claude — отдельно, в [../memory/MEMORY.md](../memory/MEMORY.md): решений и требований там нет, её потеря проекту ничего не стоит.

**Читать не подряд, а под задачу.** Сначала этот индекс, затем только файлы нужного раздела. Крупные документы разбиты на части; в них искать через `grep`, а не читать подряд.

## О проекте
**Секретарь** — личный задачник: задачи привязаны к дню, есть регулярные повторения, данные лежат на устройстве. Поставляется как PWA, публикуется на GitHub Pages. Главная цель текущего этапа — **подобрать дизайн** (решение Р-12), поэтому функционал берётся минимальным и наращивается постепенно.
**Состояние:** этап 1 закрыт — оболочка PWA опубликована на `https://greatermagistr007.github.io/secretar_v2/`. Идёт этап 2 — галерея вариантов вёрстки календаря для выбора дизайна ([plan_stage_02_calendar_gallery.md](plan_stage_02_calendar_gallery.md)). Дальше — реализация экрана «Календарь» (требование Т-11).
**Целевые поставки:** PWA сейчас, позже сайт с серверной частью (решение Р-22) и Android-приложение через Capacitor из той же сборки (решение Р-20).
**Источник истории — только этот репозиторий:** документация и код других проектов, включая прежнюю версию «secretar», источником не являются (решение Р-2).

## Соглашения по именам файлов
`product_*`, `req_*`, `backlog_*` — продукт · `rules_*` — правила работы · `plan_*`, `architecture_*` — планы и архитектура · `domain_NN_*` — домены · `mechanic_*` — механики · `infra_*`, `server_*`, `deployment.md` — инфраструктура · `release_*` — выпуски · `reference_*` — справочное · `feedback_*` — грабли (продуктовые в `docs/`, инструментальные в `memory/`) · `history_*` — хронология · `audits/` — аудиты.

## Формат файлов
YAML-frontmatter (`name`, `description`, `type: project | feedback | reference`) в начале каждого файла. Язык текстов — русский, идентификаторы — английские. Заголовки h1–h4, ссылки относительные, без лишней разметки.
